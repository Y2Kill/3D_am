# Решения по открытым вопросам ТЗ (§16, пп. 1–40)

Для каждого открытого вопроса v1.1–v1.6 принято рабочее решение (пп. 27–40 добавлены после ТЗ v1.2–v1.5, правки пп. 3, 9, 10, 15, 25 — по отчёту [03](../reports/03_TZ_v1.3-1.5_vs_prepared.md)), достаточное для начала реализации. Решения помечены как **[РЕШЕНО-РАБОЧЕЕ]**: их можно пересмотреть без переделки архитектуры, потому что точки изменения изолированы интерфейсами. Ссылки на ADR — в `ADR_log.md`.

| № | Вопрос (кратко) | Рабочее решение | Где зафиксировано |
|---|---|---|---|
| 1 | Эвристики группировки, профили импорта, UX пересмотра | Кандидат в ассет — каталог, в котором есть хотя бы один архив/модель и который не содержит подкаталогов-кандидатов (это лист дерева «моделей»). Каталог верхнего уровня под корнем импорта = контекст «канал». Профиль импорта — TOML-файл (`profiles/telegram.toml`) с правилами: `source_from_parent = "telegram_channel"`, `nested_archives = "expand"`, `max_depth = 3`, `exclusion_rules = ["macos.*", "windows.thumbs", "os.desktop_ini"]`, `group_hints = ["scale", "presupport", "nsfw"]`. UX пересмотра — дерево кандидатов с drag & drop для объединения и разделения, предупреждения цветом. | ADR-0011; `docs/architecture/import_pipeline.md` |
| 2 | Схема ZIP, манифест, пути, миграции, коллизии ID | Формат v1 со спецификацией и JSON Schema. Миграции: функции `migrate_vN_to_vN+1(json)` применяются при чтении в памяти; запись в новой версии — только по явной операции `migrate_format` или при первом изменении, после подтверждения пользователя (настройка). **Пересмотрено ADR-0035 (ТЗ v1.8 §19.4):** формат 1.0, FormatID-URN, `major.minor`, матрица возможностей; миграция повышает ревизию. | ADR-0005/0008/0010/0012; `container_manifest_v1.md` |
| 3 | Типизация метаданных, достоверность, конфликты повторного анализа | `value_origin` + `confirmed`. Правило слияния: `confirmed=true` никогда не перезаписывается автоматически; `measured` перезаписывается новым `measured` той же или более новой версии алгоритма; `inferred` перезаписывается тихо; конфликт с `user` попадает в предложения. Статусы `suggested/computed/confirmed` + `origin_detail`; предложения последующего анализа хранятся в `index.sqlite: suggestions` и не меняют ревизию, в ZIP — только предположения импорта и подтверждённые значения. **Представление в ZIP пересмотрено ADR-0035:** `metadata.claims[]` (method/evidence/review); правило приоритета пользователя и `index.suggestions` сохранены. | ADR-0013, **ADR-0028** |
| 4 | Размещение производных, выборочный экспорт, редактирование групп | `derived/<op-id>/…`. Выборочный экспорт — ZIP того же формата с **новым ID** (`derived_from` = исходный), в который попадают выбранные категории файлов (пресеты: «3D», «3D+превью», «для слайсера» = stl/3mf/obj/lys/chitubox/ctb/gcode); манифест урезается до выбранных `files[]`, а исключённые при экспорте записи **не** помечаются как исключённые при импорте. Пресет «как обычные файлы» выдаёт просто ZIP без манифеста. Группы редактируются на вкладке «Состав» ассета. **Пересмотрено ADR-0035:** производные — `generated/` и `files[]` с `derived_from`/`generation`; новый ID выборочного экспорта фиксируется событием `asset_copied`. | ADR-0005 |
| 5 | Обязательные форматы первого этапа | Архивы: zip, 7z, rar4/5, тома, split. 3D: STL (свой ридер), OBJ/MTL, 3MF, PLY, glTF (через Assimp/lib3mf). 2D: JPEG/PNG/WebP/GIF/BMP/TGA/PSD(composite), SVG, DXF (базовый). Документы (FTS): TXT, MD, RTF, PDF (плагин). G-code: метаданные + встроенные превью. Остальное — хранение и внешнее открытие. | `libraries.md` |
| 6 | Алгоритмы и пороги совпадений, группировка кандидатов, конфликты ID | Пороги по умолчанию: pHash Хэмминг ≤ 6 — «визуально одинаковые», ≤ 14 — «похожие». MinHash-Jaccard ≥ 0,9 — «одинаковый комплект», ≥ 0,3 — «частичное пересечение». Геометрия: совпадение `geom_fp` — «идентичная геометрия», расстояние дескрипторов < ε — кандидат. Группы — компоненты связности по рёбрам выбранных типов (union-find), основания каждого ребра хранятся отдельно (ТЗ 7.7.1). | ADR-0016 |
| 7 | Признаки технического мусора, приоритеты, формат исключений | Встроенные правила v1 (версионируемые): `macos.appledouble` (сигнатура `00051607` **или** путь `__MACOSX/`), `macos.ds_store` (имя + сигнатура `\0\0\0\1Bud1`), `windows.thumbs_db` (имя + OLE-сигнатура), `windows.desktop_ini`, `os.icon_r` (`Icon\r`), `sync.dropbox_cache`. Приоритет: явное решение пользователя > профиль > встроенное правило. Только «уверенные» (имя и сигнатура совпали) исключаются автоматически, остальные предлагаются пользователю. | ADR-0011 |
| 8 | GUI, СУБД, библиотеки | Qt 6 Widgets, SQLite, minizip-ng + libarchive (+7z), Assimp/lib3mf/OCCT, собственный OpenGL-рендерер. | `libraries.md`, ADR-0017 |
| 9 | API/ABI плагинов, загрузчик, UI, изоляция | C ABI v1 — **кандидат** до спайка S6; C++ SDK; жизненный цикл с `draining`; явное владение ресурсами; GUI-точки только декларативные (без `gui-qt`); изоляция — процесс `am-worker`. | ADR-0003, 0009, **0026** |
| 10 | LLM | Последняя веха (M11). Необязательный уровень `am_ai` + тестовый адаптер; движки — плагины; доступ к командам по выданному уровню `read/prepare/modify`. Сценарии отделены от LLM (веха M-S). | ADR-0023, **0027** |
| 11 | Установка/портативность, форматы настроек, CI, производительность, раскладка ZIP по папкам | TOML; `portable.flag`; CI — GitHub Actions/GitLab CI (windows-2022 + ubuntu-24.04) с vcpkg binary cache; раскладка `assets/<xx>/`. Показатели — по [плану измерений](../architecture/nfr_measurement_plan.md): нормативы только после замеров (ТЗ v1.7 §14.9.13, вопросы 41, 49). | ADR-0007, 0022 |
| 12 | Менеджер зависимостей | vcpkg manifest mode + baseline + локальный бинарный и asset-кэш. | ADR-0002 |
| 13 | Протокол фиксации и восстановления; фоновая проверка | Протокол из ADR-0006. Фоновая полная проверка выключена по умолчанию; можно включить «проверять N ГБ в день в простое». | ADR-0006 |
| 14 | Очередь и журнал, безопасные точки, идемпотентность, лимиты | `state.sqlite: jobs, op_log`; безопасные точки между файлами; идемпотентность через `op_id`; пулы по устройствам. | ADR-0015, `jobs_and_sessions.md` |
| 15 | Лимиты вложенных архивов, защита путей, UX ошибок | По умолчанию: глубина 3; суммарная распаковка ≤ 4 × размер входа + 8 ГиБ, но не больше 25 % свободного места; ≤ 100 000 записей на входной набор; коэффициент сжатия отдельной записи ≤ 1000:1 (защита от zip-бомб); пути с `..`, абсолютные и с `:` отвергаются (zip-slip) и становятся `included_renamed`. Лимиты задаются секцией `[limits]` профиля; достижение лимита — статус `incomplete{limit}` (ADR-0029). Ошибки показываются в карточке задания + `needs_decision` для частичного импорта. | ADR-0011/0012 |
| 16 | Реестр заключений, бэкап, устаревание, экспорт связей | `userdata.sqlite: relations` с `(asset, rev)`; при индексации ассета с новой ревизией связанные заключения помечаются `stale`. Экспорт и импорт связей — JSON-файл `relations.jsonl` (команда CLI). | `schemas/sql/userdata.sql` |
| 17 | UI сравнения, промежуточные результаты, массовые действия | Окно «Сравнение»: три вкладки (изображения/содержимое/метаданные).
