# T-001. Foundation по ADR-0035: UUIDv4, `Errc::incomplete`, пути и причины переименования по формату 1.0

**Статус:** ready · **Веха:** M1, шаг 0 (`docs/plan/roadmap.md`) · **Основание:** ADR-0035 пп. 4, 8, 15; спецификация §1 п. 6, §5 (`rename_reason`)

## Цель

Привести готовый код уровня `foundation` к утверждённому формату ZIP-ассета 1.0 до начала M1. Изменения узкие: ID для объектов внутри ZIP, новый код ошибки, причины переименования и суффикс коллизии по спецификации. Unicode-нормализация (NFC + case folding) сюда **не входит** — это T-002.

## Требования

### 1. `Uuid::v4()`
- Добавить `static Uuid v4();` — 122 случайных бита из того же источника, что у `v7()` (`std::random_device`). Поле версии = 4, вариант = `10xx` (RFC 9562).
- Добавить `static std::optional<Uuid> parse_canonical(std::string_view)`: принимает **только** канонический вид в нижнем регистре `8-4-4-4-12` (для чтения манифеста). Существующий `parse()` (без учёта регистра) не менять.
- `v7()`, `v7_at()`, `unix_ms()`, `shard()` не менять. Комментарий в начале `uuid.hpp` обновить: v4 — ID внутри ZIP (ADR-0035 п. 4), v7 — ID вне ZIP (библиотека, задания, снимки).

### 2. `Errc::incomplete = 15`
- Добавить в `enum class Errc` значение `incomplete = 15` с комментарием `// import/validation finished with known gaps (ADR-0035 p.15)`.
- `errc_name(Errc::incomplete)` → `"am.incomplete"`.
- Существующие числовые значения не менять (они стабильны: `static_assert` в `test_error.cpp`).

### 3. Причины переименования = словарь формата
`RenameReason` должен совпадать со словарём `rename_reason` формата 1.0 плюс `none`:

| Значение | Строка `to_string` | Когда |
|---|---|---|
| `none` | `none` | путь не менялся |
| `path_too_long` | `path_too_long` | не помещается в 200 байт |
| `invalid_chars` | `invalid_chars` | недопустимые символы; **также** компоненты `..` и префикс диска `C:` (бывший `unsafe_traversal`) |
| `encoding` | `encoding` | зарезервировано для импорта (имя получено эвристическим декодированием); маппер сам его не выставляет |
| `collision` | `collision` | совпадение с уже выданным путём |
| `reserved_name` | `reserved_name` | зарезервированное имя Windows |

- Значение `unsafe_traversal` **удалить**. Поведение защиты от zip-slip сохранить: `..` по-прежнему заменяется на `__up__`, префикс диска отбрасывается; меняется только причина — `invalid_chars`. Исходный путь сохраняется в манифесте в `entries[].path`, поэтому для аудита ничего не теряется (решение управляющего, отражено в спецификации §5).
- Приоритет причин прежний: первая выставленная причина сохраняется, кроме `path_too_long`, которая перекрывает остальные (как сейчас).

### 4. Суффикс коллизии `~<8hex>` (ADR-0035 п. 8)
- Вместо `~2`, `~3`… при коллизии добавлять перед расширением `~` + 8 hex-цифр в нижнем регистре: младшие 32 бита `fnv1a64(normalized_source_path)` (та же функция `hex8(fnv1a64(norm))`, что уже используется для длинных путей).
- Если и этот путь занят — `hex8(fnv1a64(norm + '\x1f' + std::to_string(k)))` для `k = 1, 2, …` до первого свободного.
- **Итоговый путь после добавления суффикса не длиннее 200 байт** (сейчас это не проверяется — ошибка). Если не помещается — укоротить основу имени через `truncate_utf8`, не разрывая UTF-8 и не трогая расширение и корень; причина в этом случае — `path_too_long`, если она ещё не выставлена иначе (правило приоритета из п. 3).
- Сравнение занятости пока прежнее (ASCII-свёртка регистра) — Unicode-свёртка придёт в T-002. Оставь у функции `fold` комментарий `// T-002: NFC + Unicode simple case folding (ADR-0035 p.8)`.

### 5. Корень `content/<InputID>/`
- В тестах и примерах заменить корень `content/i001/` на корень с UUIDv4, например `content/debdf916-b47c-41db-b4fd-7aa9511396f3/` (45 байт). Комментарий в `paths.hpp` (`e.g. "content/i001/..."`) обновить.
- Поведение `ZipPathMapper` от вида корня не зависит; лимит 200 байт считается для всего пути, включая корень (уже так).

### 6. CLI
- `am uuid [--v4] [count]`: по умолчанию — v7, с `--v4` — v4. Обновить строку в `usage()`.
- `am zip-path` выводит причину через `to_string` — проверить, что печатаются новые строки.

## Критерии приёмки

1. `Uuid::v4()`: тест на 10 000 сгенерированных ID — все уникальны, у всех `version() == 4`, вариант `10xx`, `to_string()` соответствует шаблону схемы `^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$` (проверить через `std::regex`).
2. `parse_canonical`: принимает канонический v4 и v7 в нижнем регистре; отклоняет верхний регистр, отсутствие дефисов, лишние символы, пустую строку. Круговой тест `parse_canonical(u.to_string()) == u`.
3. `Errc::incomplete == 15`; `errc_name` → `am.incomplete`; тест уникальности имён охватывает коды `0..15`.
4. `RenameReason` без `unsafe_traversal`; тест: путь с `..` и путь `C:/x/a.stl` → причина `invalid_chars`, путь остаётся внутри корня, `__up__` на месте `..`.
5. Коллизия: `Part.stl` после `part.stl` → `…/part~<8hex>.stl`, где `<8hex>` = `hex8(fnv1a64("Part.stl"))` — тест сверяет точное значение. Третья коллизия того же имени получает другой суффикс (через `k`).
6. Коллизия у пути длиной ровно 200 байт: результат ≤ 200 байт, расширение сохранено, UTF-8 не разорван (тест с кириллицей в имени).
7. Все тесты используют корень `content/<uuidv4>/`; строки `i001` в `tests/` и `src/` не остаётся (кроме нерелевантных).
8. Новые тесты помечены `RecordProperty("req", "ADR-0035")`.
9. `tools\build_min.cmd` — все тесты проходят (сейчас их 55; новых тестов станет больше), включая `arch_check`. Новых предупреждений компилятора нет.
10. Отчёт по `AGENTS.md` п. 5.
