# T-024. Генератор синтетических библиотек `gen_library` и первый замер К-112 (M2, P0.5 — часть 9)

**Статус:** done (принята 2026-11-20, `b1170f3`) · **Веха:** M2 · **Основание:** ТЗ v1.8 §14.1 п. 1, 3 [СОГЛАСОВАНО], §14.9 п. 2, 3, 5, 11, 13; §15 К-112; `docs/architecture/nfr_measurement_plan.md` §1–3, §5; ADR-0025 (действующие ZIP меняет только `AssetRepository`), ADR-0029 (синтетические данные — в `tests/`), ADR-0031 (возможности носителя); T-017/T-018 (`rebuild`, `sync`), T-022 (`open`, `verify`)

## Цель

1. Детерминированный генератор синтетических библиотек 100…250 000 ассетов `tests/performance/gen_library`. Генератор создаёт ассеты **только через публичный путь записи** (`catalog::Catalog::create`/`trash`), то есть каждый ZIP проходит протокол фиксации и V1–V3.
2. Скрипт замера `tests/performance/run_scale.py`: время и пиковая память операций каталога, которые уже есть в CLI, по шкале объёмов. Результаты пишутся в `tests/performance/results/` в формате JSON.
3. Первый замер на машине исполнителя. Результат — **данные, а не норматив** (§14.9.13): порогов и проверок «быстрее X» нет.
4. Бинарная часть К-112: на неизменённой библиотеке подключение и список **не читают ZIP**.

Поиск, фильтрация, первая выдача в GUI и RAM GUI из К-112 сейчас измерять нечем: они появятся в M4/M5. Строка К-112 после задачи — «частично».

## Решения управляющего (не пересматривать в задаче)

1. **Путь записи.**
   - Генератор открывает библиотеку через `catalog::Catalog::open` (`read_write`) и создаёт ассеты через `Catalog::create`, корзину — через `Catalog::trash`.
   - Прямую запись ZIP в `assets/`, копирование готовых ZIP, отключение `fsync` и любые обходы протокола фиксации **не допускаются** (ADR-0025).
   - Скорость генерации сама по себе — полезная величина: генератор измеряет её и сообщает (см. п. 7).
2. **Где лежит.**
   - Исполняемый файл `am_gen_library`: исходники в `tests/performance/gen_library/`, собирается только в конфигурации CLI (нужны SQLite и каталог), на Windows и Linux.
   - Это тестовый инструмент: в `src/`, `include/am/` и в поставку `am` не входит; `arch_check` не затрагивает.
3. **Детерминизм.**
   - Одинаковые `--seed` и `--count` дают одинаковое логическое содержимое на Windows и Linux: `asset_id`, `op_id`, `file_id`, пути и байты файлов, метаданные, выбор ассетов для корзины.
   - Генератор псевдослучайных чисел — собственный (например, splitmix64/xoshiro256** с явным отображением в диапазон). `std::uniform_*_distribution` и `std::shuffle` **не использовать**: их результат зависит от реализации стандартной библиотеки (MSVC и libstdc++ дают разные числа).
   - UUIDv4 строится из псевдослучайных байтов с выставленными битами версии и варианта.
   - Время (`created_at`, `history[].at` и т. п.) берётся с системных часов и в детерминизм не входит. Подстановка часов в `Library`/`Catalog` в этой задаче **не добавляется**. Служебный `op_id` операции `trash` (журнал фиксаций, `op_log`) тоже не входит в детерминизм: ZIP он не меняет (В-3).
   - Режим `--plan-only` не пишет библиотеку, а печатает SHA-256 логического плана (канонический текст: по каждому ассету `asset_id`, метаданные, список `(path, file_id, size, sha256)`, признак корзины). Значение для `--seed 1 --count 100` записывается в тест как константа и проверяется на обеих ОС.
4. **Содержимое ассета** (реалистичное по структуре, малое по байтам — замер касается каталога, а не скорости ввода-вывода):
   - число файлов — от 1 до 50, распределение со смещением к малым (медиана около 4);
   - типы по расширению: `.stl`, `.obj`, `.3mf`, `.step`, `.png`, `.jpg`, `.txt`, `.pdf`, `.zip` (байты синтетические, правдоподобие формата не требуется); пути с подпапками глубиной 0–2;
   - размер файла — от 64 байт до 16 КиБ по умолчанию; параметр `--content-scale` умножает размеры (для будущих замеров ввода-вывода);
   - байты файлов различны между ассетами (выводятся из seed), чтобы будущий поиск по SHA-256 не получал вырожденных данных; дубликаты внутри одного ассета не создаются;
   - метаданные ассета по SPEC §9.1: `title` (всегда), `description` (около половины), `tags[]` 0–12 из словаря около 500 строк с частотой по закону Ципфа (точных дубликатов внутри ассета нет), `categories[]` 0–3 из около 100 путей глубиной 1–3, `authors[]` 0–2, `license` (около трети), `links[]` 0–2 (`rel` из открытого словаря), `dates` (около трети);
   - в строках — латиница, кириллица и немного CJK, включая пробелы и пунктуацию; все строки — корректный UTF-8 и проходят V3;
   - `--trash-fraction` (по умолчанию 0.01) — доля ассетов, перемещаемых в корзину после создания.
   - `previews` и `custom_values` не генерируются: в API репозитория пока нет операций для них, а миниатюры каталога хранятся вне ZIP (SPEC §7) и появятся в M5/M6a. Это ограничение записать в отчёт и README.
5. **Параметры и возобновление.**
   - `am_gen_library --out <dir> --count N [--seed S] [--trash-fraction F] [--content-scale K] [--plan-only] [--json] [--assume-capabilities]`.
   - Если `<dir>` не существует, генератор создаёт библиотеку (`Library::init`). Если существует — **возобновляет**: ассеты из плана, которые уже есть в библиотеке, пропускаются; создаются недостающие. Параметры генерации хранятся в `<dir>.gen.json` рядом с библиотекой (не внутри неё); при несовпадении параметров — отказ с понятной ошибкой, без изменений.
   - Прерывание (Ctrl+C, kill) не портит библиотеку: это гарантирует протокол фиксации; повторный запуск продолжает.
   - `--assume-capabilities` передаёт `OpenOptions::capabilities` для носителей, которые не проходят производственную проверку (Linux CI, WSL); флаг явно печатается в выводе и попадает в JSON результата. На проверенном носителе Windows замер выполняется **без** этого флага.
   - Каталог по умолчанию для библиотек замера — `.cache/perf/` в проекте (уже в `.gitignore`).
6. **Скрипт замера `run_scale.py`** (Python, только стандартная библиотека):
   - вызывает `am` как отдельный процесс; для каждого объёма и операции — серия из `--repeat` (по умолчанию 5) прогонов;
   - операции: `am version` (база — стоимость запуска процесса), `am library info`, `am library list --json`, `am library sync` (неизменённая библиотека, `stat`-сверка), `am library verify` (быстрый), `am library rebuild`; `rebuild` идёт последним в серии;
   - первый прогон после генерации записывается отдельно (`first_after_generation`), остальные — в статистику: медиана, P95 (при малом числе повторов — максимум, с пометкой), минимум;
   - пиковая память процесса: Windows — `PeakWorkingSetSize` через `ctypes` (`GetProcessMemoryInfo` по дескриптору процесса до его закрытия), Linux — `ru_maxrss` дочернего процесса (`os.wait4`); единица — байты;
   - код возврата каждой операции проверяется; ненулевой код — ошибка замера, а не точка данных;
   - «холодный» кэш ОС не измеряется (нужна перезагрузка или права администратора): в результате — `"cold_cache": "not_measured"`; это открытый пункт плана измерений.
7. **Формат результата** — `tests/performance/results/<YYYY-MM-DD>-<config>.json`, формат описать в `tests/performance/README.md`:
   - `schema: "am.perf.scale.v1"`, дата, версия и коммит программы, тип сборки;
   - окружение по §14.9.2: ОС и версия, модель CPU, число ядер, объём RAM, GPU (если не определяется — `null`), тип носителя и ФС (носитель задаётся параметром `--storage "nvme-ssd|sata-ssd|hdd|…"`, автоматически не угадывается), признак `assume_capabilities`;
   - по каждому объёму: параметры генерации, число ассетов и файлов, размер библиотеки на диске, **время генерации и скорость** (ассетов в секунду), результаты операций;
   - **в файле нет** имени компьютера, имени пользователя, абсолютных путей и серийных номеров: репозиторий публикуется.
8. **Шкала первого замера** (на машине исполнителя, Windows, проверенный NTFS-носитель, Release или RelWithDebInfo — указать):
   - обязательно: 100, 1 000, 10 000;
   - 50 000, 100 000, 250 000 — выполнить, если оценка времени генерации по скорости на 10 000 не превышает 3 часов на объём; иначе — не выполнять, а записать оценку в отчёт (решение о длительном прогоне примет управляющий). Генерация возобновляемая, её можно вести частями.
9. **Бинарная проверка «не загружает ZIP при старте»** — тест на C++ с хуком `IndexerHooks::before_read` (уже существует): на неизменённой библиотеке из 200 ассетов `Catalog::open` (`read_write` и `read_only`) и `list` вызывают хук 0 раз; после изменения `mtime` одного ZIP штатный `open` по-прежнему не читает ZIP (решение T-022), а при незакрытой сессии (`writer_session = open`, имитация аварии) `open` читает ровно этот ZIP (В-1).
10. **CTest.**
    - `perf_gen_smoke` (обычный, входит в CI на Windows и Linux): `--plan-only` с константой SHA-256; генерация 100 ассетов (на Linux — с `--assume-capabilities`); `am library verify --full` → 0; число ассетов и в корзине совпадает с планом; повторный запуск — 0 новых ассетов; повтор с другими параметрами в тот же каталог — отказ; `run_scale.py --repeat 1` по этой библиотеке даёт JSON с обязательными полями и без запрещённых (п. 7). Время теста — в пределах обычных CLI-тестов.
    - `perf_scale` — полный замер по шкале, метка ctest `periodic`; в CI **не запускается** (проверить, как CI выбирает тесты, и при необходимости исключить метку, не меняя остальных заданий).
11. **Зависимости.** Новых библиотек нет: C++ — существующие модули проекта, Python — только стандартная библиотека. `vcpkg.json` не меняется; запись в `docs/research/libraries.md` не нужна.

## Тесты

`RecordProperty("req", "K-112")` (C++); метка `req:K-112` для CTest-тестов Python.

1. **План детерминирован:** `--plan-only --seed 1 --count 100` — константа SHA-256 совпадает на Windows и Linux; другой seed → другой хеш; `--count 101` → первые 100 ассетов плана совпадают с планом на 100 (план расширяем, это нужно для возобновления).
2. **Валидность:** все 100 созданных ассетов проходят `verify --full`; метаданные из плана совпадают с индексом (`title`, теги, категории, число файлов) — выборочно не менее 10 ассетов; ни один файл не дублирует байты другого.
3. **Возобновление:** генерация прерывается после K ассетов (тестовый параметр или хук), повторный запуск достраивает до N; итог совпадает с непрерывной генерацией по `asset_id` и содержимому.
4. **Несовпадение параметров:** повтор с другим `--seed` или `--content-scale` в существующий каталог → отказ, библиотека без изменений.
5. **ZIP при подключении не читаются** (п. 9).
6. **Скрипт замера:** JSON по формату п. 7; ненулевой код операции → скрипт завершается ошибкой; запрещённые поля отсутствуют (проверка по имени компьютера, имени пользователя и абсолютному пути каталога).
7. **Первый замер:** файл результата по п. 8 закоммичен в `tests/performance/results/`.

### Вопросы и принятые решения
