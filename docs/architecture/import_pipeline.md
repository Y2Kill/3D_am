# Конвейер импорта

ТЗ раздел 6 и §13.3; ADR-0011, 0012, 0014, 0015, 0025, 0029. Реализация: `src/services/import/` (уровень `services`). Чтение архивов — `src/storage/archive/`. Фиксация — `storage::AssetRepository`.

**Режим исследования (`am analyze`, ADR-0029).** Это этапы 1–3 и 6–7 без упаковки и фиксации, на тех же обработчиках, что и импорт (ТЗ §13.3.9).
- Уровень `inventory` — этап 1.
- Уровень `structure` — этапы 1–3 и 6–7.
- Уровень `deep` — дополнительно анализаторы содержимого (этап 10 без записи).

Каждый акт импорта получает фактическую полноту `inputs[].completeness ∈ {complete, incomplete, unknown}` (X-01, ADR-0037 п. 6). Достижение лимита профиля (`[limits]`) даёт `incomplete`, причина пишется в `problem` затронутых записей. Нормативного `asset.flags.incomplete` нет.

## Этапы и компоненты

| # | Этап | Компонент | Вход → выход | Ресурс |
|---|---|---|---|---|
| 1 | Обход (read-only) | `Scanner` | корни → `ScanTree` (узлы ФС: путь, размер, mtime, тип по сигнатуре — kSignatureProbeBytes, сейчас 96 байт) | io |
| 2 | Сборка томов | `VolumeSetDetector` | файлы-архивы → `VolumeSet{volumes[], complete, missing[]}` по заголовкам (+ имена как подсказка) | io |
| 3 | Предложение границ | `BoundaryProposer` + профиль | `ScanTree` → `Candidate[]{root, inputs[], context:{channel}, confidence, reasons[]}` | cpu |
| 4 | Пересмотр пользователем | GUI/CLI (`--accept-all`, `--plan plan.json`) | кандидаты → `ImportPlan` (сериализуемый JSON) | — |
| 5 | Ранние совпадения | `KnownInputMatcher` | `(name, size)`, затем SHA-256 входов → `Match[]` → политика (skip / ask / continue) | io |
| 6 | Инвентаризация содержимого | `ArchiveReader` (libarchive/7z) | входы → `EntryList` (имя: raw-байты + декодированное, размер, CRC, mtime, тип по сигнатуре) | io |
| 7 | Классификация записей | `ExclusionEngine` (правила v1) + `NestedPolicy` | записи → include/exclude/expand/keep-as-file; рекурсия для вложенных ≤ max_depth | cpu |
| 8 | Отображение путей | `PathMapper` | исходные пути → `zip_path` (ADR-0012), коллизии и переименования | cpu |
| 9 | Упаковка | `AssetBuilder` → `ZipWriter` | поток из архива → SHA-256 + Deflate/Stored в temp ZIP; SHA-256 входов параллельно | io+cpu |
| 10 | Метаданные | `MetadataExtractors` (плагины) | лёгкие экстракторы во время упаковки (STL-статистика, размеры картинок, `.url`, `.blend`-thumb) | cpu |
| 11 | Фиксация | `AssetRepository` → протокол фиксации (ADR-0006, 0025) | temp ZIP → `assets/xx/<id>.zip` + индекс | io |
| 12 | Пост-обработка | дочерние задания | миниатюры, pHash, mesh-features, FTS документов (низкий приоритет) | cpu |

## Профиль «Telegram» (пример профиля для коллекций вида `канал/модель/…`)

Ядро не содержит правил, специфичных для Telegram (ТЗ §13.2.2). Ниже фрагмент профиля; актуальный файл — [`profiles/telegram.toml`](../../profiles/telegram.toml), включая секции `[volumes]` и `[limits]`.

```toml
# profiles/telegram.toml
id = "telegram"
version = 1
[boundaries]
candidate = "leaf_dir_with_payload"      # лист с архивом/моделью
context_levels = 1                       # 1-й уровень под корнем = канал
[provenance]
parent_as = "telegram_channel"           # предположение, confirmed=false
url_files = "suggest"                    # .url → предложение, с фильтром рекламы
url_ad_patterns = ["(?i)free ?download", "(?i)extra creativity", "(?i)patreon\\.com/join"]
[nested]
action = "expand"
max_depth = 3
[exclusions]
rules = ["macos.appledouble", "macos.ds_store", "windows.thumbs_db", "windows.desktop_ini", "os.icon_r"]
[previews]
primary = ["sibling_image_largest", "archive_top_image_largest", "embedded", "render"]
[groups]
hints = ["scale", "presupport", "variant_nsfw"]
[mode]
strict = true                             # ТЗ 6.6.1
```

## Режимы ошибок

- Строгий режим: любая ошибка чтения обязательной записи переводит задание в `needs_decision` с вариантами: «пропустить ассет», «импорт частично», «повторить с другим бэкендом архивов (7z)».
- Частичный импорт (`mode = partial`, только с явного разрешения): `inputs[].completeness = incomplete`. Исход каждой записи классифицируется по факту (K-2):
  - `unavailable` — запись или том недоступны для получения;
  - `failed` — запись доступна, но чтение или декодирование завершилось ошибкой;
  - `not_processed` — операция над обнаруженной записью не выполнялась.

  Причина — в `problem{code, message_id}`. Если исход нельзя доказательно классифицировать, полнота акта — `unknown`. В индексе `assets.incomplete` вычисляется: есть Input с `completeness IN ('incomplete','unknown')`.
- Каталоговые записи архива пишутся с `entry_kind = directory`, без FileID. Тома нумеруются с 0 по позиции в наборе: внутренний детектор (`volume_detect.hpp`) считает пропуски с 1, при записи нужен перевод.

## План импорта v1 (T-028)

`am import scan` реализует обход, группировку томов **по именам**, предложение границ, ранние совпадения и классификацию файлов файловой системы. Ассеты не создаются, исходники не копируются и не меняются. Архивные записи не становятся узлами плана; раскрытие архивов и `import run` остаются следующими задачами. Проба собственного ZIP использует существующие V1–V4, как add-ready; проверка собственного ассета может читать его потоки, но ничего не извлекает на диск. Для 3MF проверяется наличие `3D/3dmodel.model` в каталоге ZIP; специализированный контейнер остаётся файлом.

### Предложение границ

- Встроенный `default`: стратегия `root`, один кандидат на выбранную папку со всеми вложенными папками или на выбранный файл. `--single` объединяет оставшиеся входы.
- `telegram`: `leaf_dir_with_payload`, `context_levels=1`. Первый уровень — контекст, второй — кандидат со всем поддеревом. Свободные файлы и архивы в контексте дают отдельные кандидаты с уверенностью low. При отсутствии полезных файлов кандидат не создаётся, каталог остаётся узлом empty/excluded_only. Недоступное поддерево даёт ask/has_unavailable, поскольку отсутствие содержимого не доказано.
- Контекст — `context.sources[]`: `{kind,name,confirmed:false}`. При нескольких уровнях сохраняются все доступные родительские предположения. Источник распространения не означает автора.
- **Уточнение В-1 управляющего:** любой распознанный готовый ZIP, в том числе не прошедший проверку, всегда выделяется в отдельный `ready_asset`. Это действует и при `--single`. Стратегия применяется к остальным входам; у оставшегося кандидата добавляется `ready_asset_separated`. Если включаемых файлов не осталось, такой кандидат не создаётся. Причина готового — `ready_asset_manifest` либо `ready_asset_invalid` (ask).
- Пользователь может перенести готовый ZIP в `new_asset` и выбрать хранение обычным файлом. `parse_plan` принимает такую правку. Ограничение «один вход из одного ZIP» относится только к кандидатам `ready_asset`.
- **Уточнение В-3 управляющего:** проба собственного формата выполняется для каждой сигнатуры ZIP независимо от ExclusionEngine. Если распознан валидный или невалидный готовый ассет и правило предлагает exclude либо ask, кандидат получает `ready_asset`/`ask`, запись — `decision=ask`, добавляется причина `ready_asset_exclusion_conflict`. Исходные `rule_id` и `confidence` сохраняются. Если ассет не распознан, применяется обычное решение исключения. Правила ExclusionEngine не изменяются; проба манифеста не раскрывает содержимое входного контейнера.
- Каждый обычный архив получает отдельный input; набор томов — один `multivolume_archive`. Свободные файлы объединяются в input file/directory. `directories[]` кандидата сохраняет ссылки на каталоги без назначения им решений. Все члены набора томов остаются в одном кандидате, даже если выбраны отдельными корнями; добавляется `volume_set_kept_together`.
- Наборы пока не подтверждаются архивным бэкендом: `confirmed:false`, `volume_set_unconfirmed`, ask. Известные тома и пропуски номеров не скрываются. `missing_indices` — нумерация существующего детектора с 1; при построении манифеста run переведёт её в позиции с 0.

Это правила профиля **версии 1**, а не закрытие открытых вопросов ТЗ 6.1.4, 6.2.7, 6.3.6 и 6.5.7. План остаётся предложением, которое пользователь редактирует.

### Источники и профили

Узлы упорядочены по байтам отображаемого UTF-8 пути в пределах корня; корни — по порядку аргументов. При одинаковом отображении порядок уточняется исходными байтами. ID последовательные: n000001, c0001, i000001, v0001. Сериализация детерминирована, кроме created_at.

Файлы открываются только на чтение: заголовок `kSignatureProbeBytes` (сейчас 96), SHA-256 при --hash, INI-ссылка .url и разрешённая проба ZIP. Тип задаёт сигнатура. Неизвестный тип, нулевой файл и возможный дубликат сами по себе не исключаются. Никакой нормализации Unicode или переименования скан не делает. Символьные ссылки и junction внутри дерева записываются как symlink/skip с `am.import.link_not_followed`; прочие reparse-теги классифицируются по правилу T-029 ниже. Выбранный корень разрешается перед обходом. UNC/NAS как источники допустимы.

Повреждённое имя отображается с U+FFFD; name_raw/path_raw сохраняют исходные байты в hex, raw_encoding — posix либо utf-16le. Это локальное представление плана: при формировании манифеста run преобразует исходные байты в нормативный Base64. Размеры — строки uint64, mtime_ns — строка целых наносекунд системной эпохи. У недоступного узла сохраняются известные атрибуты и problem; неизвестные размеры и времена не выдумываются.

toml++ разбирает профиль в application; services получает ImportProfile без TOML-зависимости. Неизвестный ключ, неверный тип, неизвестное правило исключения и неверное регулярное выражение отвергаются с `am.import.profile_invalid` и указателем ключа. Отсутствующие необязательные настройки наследуются из default. Профили встраиваются точными байтами при сборке, включая CRLF; SHA-256 относится к исходным байтам выбранного профиля. Поиск встроенных профилей на диске при запуске не выполняется.

Секции nested/previews/groups проверяются, но не применяются и перечисляются в profile.not_applied. В скане действует max_entries: достижение бюджета прекращает обход, completeness=incomplete, limits_hit содержит max_entries. Прочие лимиты проверяются, но относятся к раскрытию архивов. Численные значения встроенных лимитов — **гипотезы**, не нормативы.

Применяются только правила exclusions.rules. certain даёт exclude, probable — ask. Например, `._x.3mf` вне __MACOSX без сигнатуры сохраняется по фактическому правилу движка. Путь в __MACOSX с сигнатурой AppleDouble исключается до пробы ZIP. Конфликт имён без учёта регистра даёт case_collision; исправление имени делает run.

**T-029, правила исключений v2:** каждому правилу заданы expected_kinds. Если известный тип противоречит правилу, certain по одному имени понижается до probable, explanation_id — am.import.exclusion.signature_conflict. Для desktop.ini и Icon с CR сохраняются unknown и текстовые stl_ascii/obj_text/gcode_text/rtf; PNG, ZIP, бинарная 3D-модель или PDF не исключаются уверенно по этим именам. Проверки обязательных сигнатур AppleDouble/DS_Store/Thumbs.db не меняются. Правило готового ассета против исключения → ask (В-3 T-028) сохраняется.

**T-029, Windows-метаданные:** общая paths::node_info разделяет получение данных ОС и чистое classify_windows_node. Только SYMLINK, MOUNT_POINT и LX_SYMLINK являются ссылками. CLOUD*, DEDUP, WCI* и неизвестные теги сохраняют вид file/directory. Файл с RECALL_ON_DATA_ACCESS, RECALL_ON_OPEN или OFFLINE не открывается ради заголовка/SHA: status=unavailable, problem.code=cloud_placeholder, message_id=am.import.cloud_placeholder, entry=ask, причина has_unavailable. Размер/mtime берутся из метаданных; каталог с облачными атрибутами обходится. Нормализация корня-заглушки разрешает родителя, не открывая сам файл. ScanHooks.node_data подменяет только сырые атрибуты/тег и метаданные на уровне запроса; это тестовое внедрение отказов, не точка расширения плагинов. POSIX сохраняет symlink_status; схема import-plan v1 уже допускает строковый problem.code и не изменена.

При url_files=suggest читаются `[InternetShortcut]`/`URL=`. Префикс (?i) снимается и превращается в флаг std::regex::icase. Обычные ссылки — suggested_links с confirmed=false; рекламные сохраняются отдельно в filtered_links с ad=true и не предлагаются. Содержимое самих .url остаётся входным файлом. Сетевых запросов к URL нет.

### Совпадения и чтение библиотеки

С --library используется Catalog::open(read_only), без восстановления, записи в базы и чтения ZIP библиотеки. name_size — слабое совпадение имени (Unicode simple casefold) и размера по input_objects/files. SHA входа сравнивается с input_objects.sha256 и files.sha256 раздельно. У готового ассета сравниваются ID и ревизия: same_revision/newer/older. Это не доказательство одинакового содержимого при одинаковой ревизии.

Совпадение даёт ask. Только явный --skip-identical с --hash даёт skip, если **каждый** объект (для набора — каждый известный том) имеет sha256_input. Конфликт ready_asset_exclusion_conflict сохраняет ask даже при таком совпадении (В-3). sha256_file и name_size для пропуска недостаточны. Объединение и перезапись библиотеки в плане не выражаются.

**Уточнение В-2 управляющего:** служебные -wal/-shm библиотеки допустимы, как в T-027. Проверяется неизменность данных .sqlite, ZIP и конфигурации. Читатель использует актуальный WAL, в том числе при работающем владельце записи; immutable не подставляется. Библиотека и источники не должны пересекаться ни в одну сторону: нормализованные пути проверяются до обхода, отказ — код 2 / am.import.library_overlaps_source. Поэтому рабочие файлы SQLite не могут изменить источник. Без --library скан папки с библиотекой разрешён; .am не получает особого исключения и может добавить служебные файлы в предложение.

### Формат и проверка

`format="am-import-plan"`, `version=1`, схема `schemas/import-plan.v1.schema.json`. План хранит generator/profile/mode, абсолютные локальные roots, scan с полнотой/счётчиками, nodes и candidates. Узел содержит собственный root; поэтому ссылки кандидата могут объединять несколько корней. root/base_path кандидата — предложение границы, состав определяют ссылки inputs/entries/directories. В манифест абсолютные пути не переносятся.

parse_plan сначала проверяет строгий JSON (включая дубликаты ключей), затем схему и ссылки/семантику: уникальные ID, существование узлов и наборов, принадлежность файла не более чем одному кандидату, неделимость набора, один ZIP у ready_asset, допустимость skip. Числовые строки размера дополнительно проверяются на диапазон uint64. Ошибка — am.import.plan_invalid с JSON-указателем. Перенос узла, смена решения, удаление и объединение кандидатов допустимы при сохранении инвариантов. Контроль изменений источника по размеру/mtime/SHA выполняет будущий run.

Выход плана проверяется на нахождение внутри источников до скана (код 2). Публикация — эксклюзивный временный файл рядом, flush/close и без замены существующего выхода (MoveFileW / link+unlink). Существующий выход или ошибка записи дают 4, отмена — 3 и отсутствие плана/временного файла. Успешный неполный скан даёт 0, полнота видна в сводке. Журнал: info import.scan.started/finished, warning node_unavailable и limit_reached; путь — только FieldKind::path. Работа через исполнитель заданий появится вместе с import run.

## Выполнение плана (T-030)

`am import run --plan <file> --library <root> [--enqueue-only] [--profile economy|balanced|performance] [--jobs N]` исполняет файловые входы и готовые ассеты через `import.run` / `import.asset`. `parse_plan_view` — единственный построитель неизменяемого `PlanView`: он вызывает `parse_plan`, проверяет uint64/int64 и разрешает ссылки в индексы. JSON-ключи плана используются только построителем. Исходный план не переписывается.

До открытия библиотеки проверяется пересечение источников и библиотеки в обе стороны. SHA-256 вычисляется по точным байтам плана; полезная нагрузка содержит путь, SHA, ID кандидата и UUIDv4 будущего ассета, Input, объектов, записей, файлов и источников. Родитель восстанавливает недостающие дочерние задания после незавершённой постановки. Повторный запуск использует прежние задания: `already_imported`, `already_queued` либо `failed` с подсказкой `am jobs retry`. Удалённый или изменённый план даёт `am.import.run.plan_changed`. После фиксации повтор распознаёт свой ассет по asset_id и InputID; другой InputID даёт `asset_id_conflict`.

Уточнение В-3: любое `ask` имеет приоритет перед исполнением, включая недоступные узлы: `deferred / am.import.run.unresolved`, без дочернего задания. Сводка отмечает недоступный нерешённый узел и его problem. Явное `include` для unavailable в strict даёт `source_unavailable` до записи; в partial — запись `unavailable` и неполноту. `exclude` сохраняет известные данные без открытия, `skip` — `not_processed`. Архивный вход откладывает весь кандидат (`archive_input_unsupported`). Готовый ZIP проходит `Catalog::import_ready` без замены; существующий ID требует решения с прежней классификацией add-ready.

Уточнение В-10: перед созданием проверяются `assets/` и `trash/`. Свой InputID в активном ассете означает прежний успех без записи. Свой InputID в корзине означает `needs_decision / deferred` с asset_id: `skip` оставляет ассет в корзине; `retry` повторяет проверку после ручного restore (успех без записи) или purge (создание с прежними ID). Контекст решения отмечает `source_changed_during_import` и предупреждает, что восстановленное содержимое может отличаться от источника. Автоматического restore/purge нет. Чужой InputID либо две локации одного ID дают `asset_id_conflict`. Репозиторий независимо защищает явный ID в create/copy: проверяет обе локации под блокировкой фиксации, до временного ZIP и строки журнала; отказ — `am.repo.asset_id_exists`. `snapshot(ref, true)` допускает только чтение корзины, обычный snapshot её не видит.

Уточнение В-4: Input один на акт импорта, InputObject — каждый реально предъявленный корень (для профильной границы — существующий каталог границы). Виртуальный каталог по title_hint не создаётся. Запись привязана к объекту своего корня, path относительно него; файл-корень использует своё имя. Один каталог даёт ZIP-иерархию сразу под `content/<InputID>/`; несколько корней сохраняют отдельные префиксы имён. Отдельный ZipPathMapper резервирует имена корней, основной — имена файлов; коллизии переименовываются и отражаются как `included_renamed / collision`. При отсутствии общего base_path relative_path не выводится. title_hint используется только как title.

`name_raw` / `path_raw` из hex переводятся в Base64, encoding_guess сохраняется; доступ к источнику использует исходное native-имя. Ссылки не читаются. Происхождение хранит sources и claims `directory_inference` без review с source_refs у Input. Предложенные URL остаются только в результатах заданий; отфильтрованные URL не сохраняются.

Сначала проверяются size/mtime всех включаемых файлов. Плановый SHA проверяется по фактическим байтам упаковки. Для файлов без планового SHA после фиксации повторяется stat; изменение переносит ассет в корзину, failed-результат сохраняет asset_id. Частичный режим откатывает попытку при структурно идентифицированной ошибке чтения источника, помечает файл failed и повторяет без него. Каждая попытка заново проверяет свежесть; не более числа включаемых файлов плюс один, каждый файл исключается не более одного раза. Ошибки библиотеки/ZIP не вызывают такой повтор.

std::stop_token проходит через CreateRequest / ImportReadyRequest в commit. Межфайловые/блочные проверки и точки до after_verify / replace удаляют временный ZIP и prepared/verified-строку журнала. После начала replace отмена игнорируется; завершённая фиксация побеждает позднюю остановку.

Гарантия параллельности: чтение метаданных и предварительное хеширование источников выполняются вне блокировки каталога. Регистрация обработчиков держит общий mutex для снимков, Catalog::create/import_ready/trash и записи итогов операций; упаковка, проверка, фиксация и обновление индекса сериализованы целиком. Catalog дополнительно имеет собственный mutex. Commit journal использует отдельное SQLite-соединение; StateJobStore и OperationLog защищают своё общее соединение SQLite mutex на всю операцию. JobContext не вызывается из критической секции каталога. Четыре параллельных кандидата проверяются с полной верификацией индекса и ZIP.

Один `import.asset.finished` в журнале операций на созданный/размещённый ассет содержит SHA плана, кандидата, asset_id и итог; повтор после фиксации проверяет существующую запись по job_id. Пропуски/отложенные кандидаты находятся в результате родителя. Коды CLI: 0 — выполнено (или постановка), 2 — аргументы/план, 3 — решение/отложено/остановка, 4 — отказ.

## ZIP как вход (T-031)

Скан пишет `am-import-plan` v2: `archives[]` содержит состояние и сводку каждого обычного ZIP, `archive_entries[]` — все записи центрального каталога в исходном порядке, включая дубликаты. Решение кандидата ссылается ровно на один `node` или `archive_entry`. V1 читается; архивный вход v1 откладывается с `archive_plan_rescan_required`, прочие входы выполняются по T-030. RAR/7z и наборы томов остаются отложенными (`archive_input_unsupported`, `volume_set_unsupported`).

Входной ZIP читает только `storage/archive/zip_input`, поверх существующего структурного читателя. Входной режим читателя отличается от режима ассетов только допуском точных дубликатов имён. Доступ — по индексу, поиска по имени нет; общий локальный заголовок и пересечения по-прежнему отвергаются. AssetRepository, add-ready, verify и golden используют строгий режим. Нейтральный ProbeContext содержит бюджет, callback проверки времени, stop_token и callback открытия; зависимости asset_zip от archive нет. Дополнительная проба первого manifest.json выполняется только при дубликате в контекстной перегрузке: доказанный собственный формат означает ready_asset_invalid. Прежняя перегрузка пробы дополнительного чтения не делает. Проверка манифеста расходует общий бюджет один раз; при исчерпании архив получает limit_exceeded.

Обязательный `profile.limits` сохраняет все пять лимитов исходного профиля. Run использует этот снимок, ограниченный безусловными пределами, и не читает профиль заново. Ручная правка снимка допустима; profile.sha256 описывает исходный файл профиля и со снимком не сверяется. В результате задания отражаются действующие значения и источник plan/unconditional. Общий ReadBudget учитывает фактические распакованные байты всех записей, образцов, проходов и частичных повторов задания; время считается на контейнер, включая структуру и хеширование. Коэффициент проверяется после 1 МиБ выхода записи (гипотеза O-17). Превышение лимита в любом режиме прерывает кандидата без ассета. max_temp_bytes сохранён, но not_applied: извлечённых временных файлов нет.

Имена декодируются по bit11, валидному 0x7075 с CRC, строгому UTF-8, затем догадке кодовой страницы. Исходные байты хранятся hex в плане и Base64 в манифесте при отличии от отображения; для опасных имён и дубликатов они сохраняются также при совпадении UTF-8. Догадка не блокирует импорт и явно отмечается. Опасные пути требуют ask; после include назначение проходит NFC, удаление недопустимых управляющих символов и ZipPathMapper. Ссылки и специальные записи учитываются как not_processed, без чтения содержимого и разыменования.

Узел ZIP — внешнее условие для его записей: include применяет их решения, ask откладывает кандидата, exclude исключает все записи с by/rule узла без чтения данных. Исключение внутреннего каталога распространяется на его потомков. Зашифрованные и неподдерживаемые записи с include останавливают строгий импорт; частичный сохраняет unavailable и incomplete. Повреждение отдельной записи допускает только ограниченный частичный повтор без неё, с failed; ошибки назначения, подмена контейнера и лимиты повтор не разрешают. Нечитаемый каталог ZIP не допускает частичного импорта. При явном exclude остаётся объект архива без выдуманных записей, а причина — в результате задания.

Архив файловой системы, в том числе sub/model.zip внутри каталога, отражается самостоятельным верхнеуровневым InputObject archive с relative_path. Родительской файловой записи ZIP в объекте каталога нет; parent_object_id, parent_entry_id и nested_action не заполняются. Полнота учёта означает: каждый узел отражён ровно записью или объектом. Одиночный архив имеет ту же форму с relative_path, равным имени. Включённый архив получает обязательный потоковый SHA-256; для полностью исключённого используются только известные метаданные. Содержимое одиночного ZIP помещается прямо в content/InputID; при смешанном входе sub/model.zip раскрывается под sub/model/, коллизии с существующими каталогами разрешаются переименованием префикса.

Вложенные ZIP/RAR/7z не раскрываются: ask, include = файл плюс объект nested_action=preserve, exclude = запись и объект nested_action=exclude; parent-ссылки относятся только к записи внутри архива. Внутри ZIP специализированный контейнер распознаётся по расширению без проверки содержимого; проверка внутреннего каталога — вместе с раскрытием вложенных архивов. Для ZIP-сигнатуры и .3mf используется include / probable / specialized_container_unverified, detected остаётся archive.zip, объекта вложенности нет. Необязательная проба Stored-3MF не реализована. AppleDouble исключается правилом до этой классификации. Run исполняет план, не переопределяя тип по содержимому.

Перед каждой попыткой проверяются stat, порядок и метаданные всех записей по index, raw_name, размерам, CRC и методу, затем SHA контейнера. AssetRepository повторно открывает ZIP в preflight и при упаковке; читатели кешируются по архиву и проходу. Замена между проходами — source_changed; CRC/обрыв конкретной записи — структурный SourceFailure с FileID. После фиксации stat проверяется для архива также при наличии SHA в плане; изменение переносит ассет в корзину по правилу T-030 В-10. UUID архивных файлов, записей и вложенных объектов выдаются в попытке, не сохраняются в params_json; InputID и верхнеуровневые object ID сохраняются. Повтор после фиксации распознаётся по InputID.

## Вложенные ZIP (T-032)

Скан пишет план версии 3. Вложенный ZIP идентифицируется записью-родителем: элемент `archives[]` имеет либо `node` (архив файловой системы, `depth = 1`), либо `entry` (ID записи родителя), а также `depth`, `sha256` и `access` (`range` или `temp`). `archive_entries[].archive` ссылается на `node` или на `entry`. Родитель стоит в `archives[]` раньше вложенного архива, поэтому ссылок по кругу быть не может.

Доступ. Stored-запись читается поддиапазоном родителя после одного прохода с проверкой CRC. Сжатая запись распаковывается во временный файл в `<library>/.am/.am-tmp/import/<uuid>/`. Файл живёт, пока жив последний читатель или поток, а каталог — пока идёт скан или попытка. Без библиотеки сжатый вложенный ZIP не перечисляется: `ask` с `nested_archive_temp_unavailable`, скан `incomplete`. В run каждое открытие (проверка плана, preflight и упаковка) материализует архив заново и сверяет его SHA-256 и перечень записей с планом.

Лимиты. `max_depth` берётся из профиля (`[nested] max_depth`, по умолчанию 3) с безусловным потолком 8. Записи глубже лимита получают `ask` с `nested_archive_depth_limit`, а `limits_hit` — `max_depth`. `max_unpacked_bytes` суммирует фактические байты всех уровней в одном задании. `max_temp_bytes` ограничивает пиковый объём временных файлов. Совпадение SHA-256 вложенного архива с предком даёт `ask` с `nested_archive_cycle`. Все значения — гипотезы O-17.

Решения. `[nested] action = expand` (синоним `extract`) даёт `expand` для перечисленного вложенного ZIP, а при отсутствии действия — `ask`. Для `preserve` и `exclude` содержимое не читается. Решение `expand` допустимо только для записи с перечисленным вложенным архивом. Правила исключения действуют до раскрытия на каждом уровне. Записи вложенного архива принадлежат кандидату верхнего уровня.

Манифест. Запись родителя получает `excluded` и `exclusion {rule: nested_extract, by: profile|user}` без `file_id`. Объект: `nested_action: extract`, `sha256`, ссылки на родителя, без `relative_path` (`container_manifest_v1.md`). Размещение: `a/inner.zip` → `a/inner/`, внутри размещения родителя; коллизии разрешает тот же `ZipPathMapper`.

Не входит: RAR/7z внутри ZIP (по-прежнему `ask` сохранить/исключить), отдельные кандидаты из вложенных архивов, общая квота временного места на одновременные задания.

3MF (этап 32b). Запись с ZIP-сигнатурой и расширением `.3mf` открывается тем же доступом и с теми же лимитами, что вложенный ZIP, но проверяется только центральный каталог. Есть запись `3D/3dmodel.model` (сравнение по ключу коллизий путей) → `include`, `certain`, `specialized_container_verified`; архив в `archives[]` не попадает, объект вложенности не пишется. Нет такой записи → архив перечисляется как вложенный, запись получает `ask` с `specialized_container_unverified` (сохранить файлом или `expand`); профиль `expand` такой 3MF автоматически не раскрывает. Не удалось прочитать (нет временной области, глубина, лимит, повреждение) → итог T-031: `include`, `probable`, `specialized_container_unverified`. Неподтверждённый 3MF открывается один раз: тот же объект используется для перечисления.

Уборка сирот (этап 32b). Восстановление при открытии библиотеки (`commit::recover`) проходит подкаталоги `.am/.am-tmp/import/`. Возраст подкаталога — по самому свежему `mtime` среди него и его содержимого, так как запись во вложенный файл не обновляет `mtime` верхнего каталога. Подкаталог моложе `orphan_age` пропускается. Если какой-то файл занят (эксклюзивное открытие даёт `locked`), подкаталог пропускается целиком. Иначе он удаляется. Общий каталог `import/` не удаляется никогда.
