# Обзор архитектуры

Основа — ТЗ §12 (v1.4+) и [ADR-0024](../decisions/ADR_log.md#adr-0024-уровни-архитектуры-и-граф-зависимостей-заменяет-adr-0004).
Архитектура — модульный монолит: одна CMake-цель на уровень, внутренние библиотеки статические, внешние плагины подключаются динамически.

Матрица разрешённых зависимостей задана в ADR-0024. Проверяется она двумя способами:
- `FORBID` в `am_add_module` — прямые связи при конфигурации CMake;
- `tools/arch_check/arch_check.py` — правила `#include`, циклы и транзитивные связи в графе CMake (ctest-тест `arch_check`).

## Карта каталогов репозитория

| Путь | Содержимое |
|---|---|
| `docs/` | `tz/` — ТЗ и черновики, `reports/`, `research/`, `decisions/` — ADR, `architecture/`, `specifications/` — формат контейнера, `plan/`, `developer/` |
| `schemas/` | JSON Schema манифеста (далее — сценариев, анализа, эталонов), SQL-схемы трёх баз |
| `profiles/` | профили импорта: правила, специфичные для источника, лимиты, схемы имён томов |
| `cmake/modules`, `cmake/toolchains` | модули CMake (опции, предупреждения, `am_add_module`), toolchain-файлы |
| `include/am/<level>/…` | публичные заголовки уровней |
| `src/<level>/…` | реализация уровней: `foundation`, `contracts`, `domain`, `jobs`, `storage`, `processing`, `services`, `automation`, `plugin_runtime`, `ai`, `application` |
| `src/application/{cli,gui,worker,common}` | исполняемые файлы и общий манифест Windows (longPathAware, UTF-8) |
| `sdk/include/am/` | отдельный SDK плагинов: ABI-черновик `am_plugin.h` (ADR-0026) |
| `plugins/<id>/`, `plugins/examples/` | встроенные и внешние плагины, пример для SDK |
| `tests/unit`, `integration`, `regression`, `fixtures`, `performance`, `plugins`, `real` | тесты. Синтетические fixtures генерируются; реальные данные — только через реестр `tests/real/registry.json`, с чтением на месте (ADR-0029) |
| `tools/` | `arch_check/`, `tz_audit/`, `inventory/` — скрипт владельца; позже `fixtures/`, `coverage/` |
| `packaging/{windows,portable}` | сборка поставки: установщик и портативный ZIP |

## Ключевые потоки данных

1. **Исследование без импорта** (ADR-0029): `am analyze` = Scanner → ContainerProbe → ArchiveWalk → BoundaryProposer → отчёт MD+JSON со статусами полноты. Ассеты не создаются, источники не меняются.
2. **Создание ассета:** те же стадии → ImportPlan → ExclusionEngine → PathMapper → AssetBuilder (ZipWriter + SHA-256) → `AssetRepository.commit` → Indexer → событие `AssetCreated`.
3. **Изменение ассета** (ADR-0025): `ChangeRequest{ref, expected_rev, ops[]}` → блокировка ассета → новый временный ZIP (неизменённые записи копируются raw) → проверка → замена с сохранением снимков активных читателей → индекс → событие.
4. **Чтение:** `AssetSnapshot` (дескриптор + ревизия + манифест) — согласованное состояние на время чтения.
5. **Восстановление индекса:** перечислить `assets/**.zip` → прочитать маркер и манифест (только центральный каталог и 2 записи) → upsert → удалить строки, ZIP которых больше нет. `userdata.sqlite` не затрагивается.
6. **Команды и сценарии** (ADR-0027): GUI, CLI, сценарий и LLM-адаптер вызывают команды реестра. Для сценария и LLM действует проверка выданного уровня `read/prepare/modify`. Изменяющие шаги исполняются как задания.
