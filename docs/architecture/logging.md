# Журналы и локальная диагностика

T-027; ADR-0024, ADR-0032, ADR-0034; ТЗ §14.4.2, §14.4.9, §14.6. Файловый технический журнал программы отделён от пользовательского `op_log` библиотеки. Он не заменяет историю операций и не меняет результат операции при ошибке записи.

## Фасад и время жизни

`am::log` находится в foundation, использует стандартную библиотеку и API ОС. Приёмник — единственный глобальный объект журнала, хранится в atomic shared_ptr. По умолчанию он отсутствует. `enabled` выполняет одну атомарную загрузку и проверяет уровень. `AM_LOG` проверяет уровень до построения полей. Уже начавшаяся запись удерживает свой приёмник при конкурентной замене.

`Scope` — вложенный стек контекста текущего потока; уничтожается в том же потоке в порядке LIFO. Внутренняя область дополняет внешнюю, явные заполненные значения `Record.context` имеют приоритет. Для передачи контекста в поток используются `current_context()` и новая область в потоке. Исполнитель переносит контекст и добавляет job_id; Catalog добавляет library_id, протокол фиксации — asset_id/operation. Неизвестные значения контекста сериализуются как null.

Приёмник spdlog находится только в application и существует до отключения/замены последней удерживаемой ссылки. Он не регистрируется в глобальном реестре spdlog; периодический сброс выполняет собственный поток с прерываемым ожиданием. Выход CLI записывает app.exit, отключает приёмник, завершает поток и сбрасывает буфер.

## Формат записи

Одна UTF-8 строка JSON с завершающим LF; версия `v=1`, схема `schemas/log-record.v1.schema.json`. Поля: ts (UTC RFC3339, миллисекунды), level, component, event, msg, pid, tid, ctx, fields, kinds. error появляется только при ошибке. Контекст всегда содержит job_id/asset_id/library_id/operation.

Уровни: trace, debug, info, warning, error, critical. Поля плоские: строки, int64, uint64, bool, double. Последний повтор ключа побеждает, в том числе при изменении kind. Ключи соответствуют `^[a-z][a-z0-9_]*$`; недопустимые ключи пропускаются с truncated. kinds содержит только path/name. Неизвестные done/total прогресса не подменяются числами и не добавляются в fields.

Собственный сериализатор foundation сохраняет uint64 точно, экранирует управляющие символы, заменяет некорректный UTF-8 на U+FFFD и ставит utf8_repaired. NaN/Infinity/-Infinity записываются строками. error содержит машинный и числовой код, severity, component/operation, message_id/message/detail, контекст и actions. Причины разворачиваются в массив до 16 элементов, остаток отмечается cause_truncated.

**Гипотезы:** предел текста — 4 КиБ, записи — 64 КиБ. Усечение сохраняет границы UTF-8, заменяет хвост на многоточие и ставит truncated. При превышении общего бюджета уменьшается число полей, затем бюджет строк; сохраняется корректный JSON. Ошибка сериализации даёт пустой результат для учёта отброшенной записи. Очень малый пользовательский бюджет, не вмещающий структуру, также даёт пустой результат.

## Файлы и включение

CLI пишет файл только при глобальном `--log-dir` либо `AM_LOG_DIR`; явная опция имеет приоритет. Уровень — `--log-level` / `AM_LOG_LEVEL`, по умолчанию info. Каталог GUI по умолчанию остаётся M5. Нет записи в профиль пользователя по умолчанию.

Имя `am-<yyyymmddThhmmssZ>-<pid>.jsonl`, ротации `.1.jsonl`, `.2.jsonl`; при повторном открытии в ту же секунду выбирается следующее свободное UTC-имя без перезаписи. spdlog используется только как rotating_file_sink_mt с шаблоном `%v`, JSON через fmt не формируется. Windows CLI, тестовый процесс и helper используют существующий UTF-8/longPathAware manifest.

**Гипотезы:** 10 МиБ на файл, три файла на процесс, общий лимит 100 МиБ, периодический flush каждые 2 с. Warning+ сбрасывается синхронно. При открытии самые старые по mtime соответствующие шаблону обычные файлы удаляются до общего лимита. Посторонние файлы, ссылки и файлы с PID текущего процесса сохраняются. Если защищённые файлы сами превышают лимит, их сохранность имеет приоритет; последующий процесс сможет убрать прежние журналы.

Сбой записи увеличивает счётчик; при восстановлении записи и при закрытии предпринимается запись warning log.dropped с count. В период недоступности потеря самого уведомления не вызывает рекурсию. При невозможности открыть каталог возвращается am.log.open_failed; CLI выдаёт предупреждение и продолжает без файла. Приёмник ничего не выводит в stdout/stderr. Fault hook before_write — только внедрение отказа экземпляра в тестах, без повторного входа в тот же приёмник.

## События

| Событие | Уровень | Контекст и поля |
|---|---|---|
| app.start | info | version, command (только имена подкоманд), os, arch |
| app.exit | info | exit_code, duration_ms |
| cli.error | error | структурированная error |
| library.open | info | library_id; mode, recovered, jobs_requeued, jobs_failed, unclosed_session |
| library.open_failed | error | error |
| library.warning | warning | error открытия, индексирования или журнала операций |
| commit.phase | debug | asset_id/operation; op_id, phase: prepared/verified/committed/indexed |
| commit.aborted | warning | op_id, error; до замены исходника |
| commit.recovered | info | op_id, outcome |
| job.started | info | job_id и перенесённый library_id; type, attempt, state |
| job.finished | info/warning/error | уровень по исходу T-026; type, attempt, state |
| job.progress | trace | job_id; известные done/total, unit, stage |
| db.corrupt | error | database: state/userdata/index; unknown для другого SQLite-файла; error |
| log.dropped | warning | count |

Пути размещаются только в FieldKind::path, имена файлов/ассетов — в FieldKind::name. msg/event не содержат путей. Нельзя писать пароли, токены, содержимое файлов и params_json целиком. Технический текст — английский; пользовательский вывод использует каталог сообщений.

## Экспорт

`am diag export <out.zip> [--log-dir <source>] [--library <dir>] [--since <RFC3339>] [--dry-run]`. Опция log-dir после diag export обозначает источник; глобальная опция до подкоманды включает собственный журнал CLI. Затем применяется AM_LOG_DIR. Недоступный явно заданный источник — ошибка 4; отсутствующий/недоступный источник из окружения даёт экспорт сведений о системе без журналов. dry-run подавляет включение файлового журнала CLI и ничего не записывает.

ZIP содержит diagnostics.json по схеме diagnostics.v1, logs/ с обезличенными JSONL и необязательный library.json. В library.json — UUID библиотеки, версии/режимы чтения баз, счётчики по health/in_trash, capabilities, тип носителя и последние до 1000 записей op_log. Catalog открывается read_only; запросы работают с базами, индексатор ZIP не запускается. Наблюдатель before_read проверяет отсутствие чтений ассетов.

Обычный вывод не включает идентичности ОС. Сведения о системе содержат только OS/version/arch, число CPU и доступный объём физической памяти. Нет дампов и отправки данных. Экспорт использует локальные файлы: UNC, сетевые диски/известные сетевые mount-типы и пути со ссылками/reparse points отвергаются до чтения содержимого. Символьные ссылки в каталоге журналов не читаются. Пользовательские ZIP ассетов и их содержимое не открываются.

Обезличивание проходит по всем строкам и ключам JSON, включая вложенные error и op_log.detail; числовые лексемы копируются через foundation JSON tree без округления. Поля path/name и error.detail заменяются токенами. Строка с абсолютным путём или одним из приватных корней заменяется целиком: частичный путь и пробелы не остаются в техническом сообщении. Имя пользователя/хоста берётся из ОС и переменных окружения; замена регистронезависима, по границам слов Unicode 17.0.0 (категории L/M/N/Pc из закреплённого UnicodeData.txt).

Токен `<path:xxxxxxxx>` / `<name:xxxxxxxx>` — первые восемь hex HMAC-SHA-256 через OpenSSL EVP, ключ — 32 случайных байта каждого экспорта. Ключ не попадает в ZIP. Одинаковое значение сохраняет токен в пределах экспорта, другой экспорт получает другой ключ. Расширения имён файлов сохраняются; UUID в полях asset_id/job_id/library_id/op_id остаются. Неразбираемые JSON-строки пропускаются и учитываются в dropped_lines; при since туда же попадают строки без разбираемого времени. Фильтрация учитывает UTC-смещения и дробные секунды.

Архив создаётся во временном файле рядом с выходом и публикуется без замены: MoveFileW / link+unlink. Существующий выход сохраняется, при ошибке временный файл убирается. Коды: 0 — успех, 2 — аргументы/время, 4 — недоступный источник/библиотека/выход или невозможность публикации. Ни один путь, имя пользователя/хоста или ключ обезличивания не должен попасть в отчёт измерений.
