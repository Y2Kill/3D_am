Программа для каталогизации и управления 3Д (2Д) ресурсами (модели, векторы, джи-код для станка и подобное).
Каждый ресурс хранится в зип-архиве (программа может работать с ними на лету). содержит предпросмотр (как 3Д так и 2Д) причем предпросмотр 3Д ресурса может быть представлен в виде приложенной к нему картинки (или нескольких).
в каждом ресурсе хранятся его метаданные (название, происхождение, автор, источник и другие - набор полей обсуждаемый и должен быть легко модифицируемым), так же копии данных всех хранятся в единой базе.
программа должна уметь преобразовывать в свой формат хранения стандартные способы представления таких ресурсов (архивы, изображения и прочее).
функциональные меню программы - легко расширяемые сама программа - максимально модульная.
в работе используются доступные готовые модули и библиотеки (ассимп, и подобные).
перед началом работ, перед реализацией каждого модуля, проводится поиск подходящих библиотек и решений.
программа позволяет конвертировать 3д ресурсы из одного формата в другой.
все метаданные ресурсов перед сохранением в формате программы сохраняются (имена файлов оригинала, контрольные суммы, размеры, другие доступные данные) для последующего поиска дубликатов, ответов на вопрос - а есть ли у нас уже этот ресурс или нет, стоит предусмотреть возможность "поиска" по изображению (поиск похожих, поиск совпадающих - что сможем сделать).
возможно стоит предусмотреть использование простой локальной ЛЛМ, которая сможет проводить поиск, частичный анализ, запускать заранее скомпонованные сценарии анализа, поиска, сопоставления и подобные процедуры.
язык С++ - для максимальной скорости работы с 3д.
структура файла ресурса - обсуждаема и расширяема. может содержать 3д модели, изображения и другие типы файлов.

данный документ подлежит преобразованию в ТЗ и является только исходным сырьем.

пример исходных файлов находится локально в директории d:\!!!_USER_FOLDERS\Downloads\Telegram Desktop\3d_Models\ (только чтение). содержимое директории следует "проиндексировать" (прочитать) включая содержимое архивов для составления представления о том, что может быть, как это может быть организовано, какие файлы могут быть избыточными (лишними. к примеру есть архивы в которых могут быть директории с идентичными именами файлов, но в одной они нормальные, скажем так, а в другой - все одного размера (если верно помню это как-то связано с макОС).
