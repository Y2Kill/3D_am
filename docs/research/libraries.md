# Исследование библиотек и внешних компонентов (наполнение раздела 17 ТЗ)

**Статус документа (ADR, Р-1, 2026-11-06).** Выбор технологий здесь — **«Предложено для §17»**, а не окончательное утверждение. ТЗ требует выбирать библиотеки по результатам исследования (§12, вводный абзац; §17), и этот документ и есть такое исследование. ТЗ v1.6 переносит его в §17 как **рабочий выбор**. Значок ✅ означает «рабочий выбор для реализации», а не утверждение в ТЗ. Отказ от варианта или его замена оформляются новой ADR.

**Дата:** 2026-11-06. **Статусы:** ✅ выбрано · 🟡 выбрано условно (подтвердить спайком M0) · 🔵 опционально/плагин · ⛔ отклонено.
**Версии** окончательно фиксируются commit-ом `builtin-baseline` vcpkg на этапе M0 (см. ADR-0002). В столбце «Ориентир» — версия, актуальная на момент исследования.
**Политика лицензий (ADR-0021):** в ядре — только пермиссивные лицензии (MIT/BSD/Apache/Zlib/BSL/PD). LGPL допускается при динамической компоновке (Qt, OCCT, FFmpeg). GPL — только в отдельно поставляемых плагинах и не в базовой поставке.

| Задача | Выбор | Ориентир | Лицензия | Статус | Обоснование / альтернативы |
|---|---|---|---|---|---|
| Запись и чтение **собственного** ZIP-контейнера | **minizip-ng** | 4.0.x (Arch собирает 4.2.2) | Zlib | ❌ для контейнера: чтение — нет (T-007), запись — нет (T-008) | **Чтение (T-007, решение управляющего 2026-11-11):** собственный разбор структуры (EOCD, ZIP64, центральный каталог, сверка локальных заголовков) + потоковый `inflate` zlib. API minizip-ng не показывает перекрытие диапазонов данных, расхождение локального и центрального заголовков и точные границы Deflate-потока, а без этого защита ТЗ §19.4.17 невозможна. **Запись (T-008, решение управляющего 2026-11-11):** собственный писатель + потоковый `deflate` zlib. Raw-копия должна проверяться одним проходом по тем же байтам, что пишутся, с бюджетом читателя T-007; размещение полей ZIP64 должно совпадать с тем, что принимает наш читатель (ZIP64 EOCD — только при насыщенном поле EOCD, иначе лишние байты); нужен детерминированный вывод для golden ZIP, политика extra fields «не вслепую» (O-15) и внедрение отказов приёмника. Порт остаётся в `vcpkg.json` (тянет `zlib`; возможное использование — плагин извлечения текста DOCX/XLSX); замена на явный `zlib` — при пересмотре зависимостей. Ниже — исходная оценка. Потоковая запись записей (SHA-256 считается в том же проходе — ТЗ 5.5.1), **raw-копирование сжатых записей без перекомпрессии** (быстрое безопасное обновление через новый ZIP — ТЗ 4.6), ZIP64, флаг UTF-8, AES не нужен. ## 17.10 Прочее

- **FastStone Image Viewer** — UX-референс (согласовано в ТЗ), не зависимость.
- **Спецификации:** APPNOTE.TXT (PKWARE ZIP, вкл. ZIP64, бит 11, extra 0x7075), RFC 9562 (UUIDv7), 3MF Core Spec, AppleDouble (RFC 1740), RAR5 technote (rarlab), формат CTB (описание из UVtools).
- **UVtools** — референс форматов фотополимерных файлов (AGPL; только документация, код не используем).
- **SPDX License Expression** (`license.spdx`, O-14 п. 3; T-011) — собственный разбор грамматики SPDX 2.3 Annex D в `am_domain`, без библиотеки: грамматика небольшая, а готовые разборщики на C++ в vcpkg не найдены и тянули бы список лицензий. Принадлежность идентификатора к списку лицензий SPDX не проверяется: нет данных списка и правила их обновления; при необходимости — отдельное решение с данными SPDX License List (CC0).
- **Каталог сообщений CLI** (T-012) — английский TOML-ресурс `resources/messages/en.toml`, разбирается toml++ 3.4 (уже в `vcpkg.json`), встраивается в исполняемый файл при сборке (без поиска файла при запуске). Отсутствующий ключ — откат к `Error::message` (ADR-0032 п. 3); полнота проверяется тестом.
- **UCUM** (единицы X-02) — движок **не выбран** (открытая поддеталь X-02). До выбора V3 сравнивает единицы только как точные строки, разные единицы — `unverifiable` (T-011).
