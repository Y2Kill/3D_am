## 4. Проблемные случаи, обязательные для поддержки

### 4.1. Служебные данные macOS — 6 135 записей AppleDouble/`__MACOSX` и 214 `.DS_Store`/`Thumbs.db`

- Это **~21 % всех записей** внутри архивов. Без фильтрации ассеты будут засорены.
- Именно об этом случае в `description.txt` сказано «все одного размера». Надёжный критерий — **сигнатура AppleDouble `00 05 16 07`** в первых 4 байтах (надёжнее размера).
- Пример `anime+23.zip::__MACOSX/anime+23/._anime+23.3mf`: файл с расширением `.3mf` — на деле AppleDouble. Инвентаризатор попытался открыть его как ZIP и получил ошибку. **Вывод:** правило исключения применяется **до** раскрытия вложенных контейнеров.

### 4.2. Многотомные архивы и имена, испорченные Telegram

- `X.part2.rar … X.part4.rar` — стандартное именование, но в одном наборе **тома 2–4 содержат только заголовки каталогов с размером 0** (errors.txt). Это признак неполного или повреждённого набора.
- `Sylvanas…rar`, `Sylvanas… (2).rar` … `(5).rar` — **тома RAR, переименованные Telegram** при скачивании (суффикс ` (N)` вместо `.partN`). Флаги `Split After = +` и `Split Before = +` и `Volume Index` в заголовках подтверждают, что это один набор.
  **Вывод (ADR-0011, ADR-0029):** суффикс ` (N)` — общая схема `copy_suffix`, настраиваемая профилем (`[volumes]`), а не правило ядра. Набор томов определяется **по заголовкам** (флаги тома, номер тома, совпадение «отпечатка» архива), а не по именам. Именные шаблоны (`.partN.rar`, `.rNN`, `.NNN`, ` (N)`) — только подсказка для группировки.
- `.001…004` (7z/zip split) — 11 файлов; это простая конкатенация, читается как один поток.

### 4.3. Файлы с неверным расширением

- `Blaze-attached.zip`, `Madox Pilot and Engineer Tora.zip`, `Nimi Nightmare - Vtuber.zip` — «File is not a zip file». Вероятно, RAR или 7z с расширением `.zip` либо обрезанная загрузка. **Вывод:** тип контейнера определяется **по сигнатуре** (`PK\x03\x04`, `Rar!\x1A\x07\x00`, `Rar!\x1A\x07\x01\x00`, `7z\xBC\xAF\x27\x1C`), расширение только подсказка.

### 4.4. Длинные пути — **2 980 путей длиннее 260 символов**, максимум 428

- Полный путь «корень коллекции + путь в архиве» превышает `MAX_PATH`. При распаковке на диск (внешнее редактирование, конвертация) это сломает обычные Win32 API.
- **Решение (ADR-0012):** везде внутри использовать `\\?\`-префикс и `longPathAware` в манифесте приложения. Пути внутри ZIP-ассета нормализуются: если путь длиннее 200 символов, сохраняется **укороченная форма** с хеш-суффиксом, а исходный путь пишется в манифест (статус `included_renamed`, причина `path_too_long`). Рабочие директории сессий создаются с короткими корнями (`<lib>/.am/s/<8hex>/`).

### 4.5. Кодировки имён в ZIP — 1 701 запись с не-ASCII именем, из них ~1 207 с признаками mojibake

- Пример: `Azerama ΓÇô Digimon` — это UTF-8 тире `–` (`E2 80 93`), прочитанное как CP437. Встречаются CJK-имена (`P2457-Tiefling武僧英雄…`), русские, эмодзи-подобные символы (`✧`).
- **Решение (ADR-0012):** порядок определения: флаг UTF-8 (бит 11) → extra-поле Info-ZIP Unicode Path (0x7075) → строгая проверка на валидный UTF-8 → эвристика CP866/CP1251/GBK/Shift-JIS/CP437 → ручное указание кодировки для архива. **Исходные байты имени всегда сохраняются** в манифесте (`name_raw_b64`), если это не валидный UTF-8.

### 4.6. Вложенные архивы — 227 (195 zip, 31 rar, 1 7z)

- Встречаются «архив с вариантами внутри» (`Abe3D_Mileena.rar::1_4 Pre support.rar`, `1_6 Scale…rar`) — это **варианты одного ассета**, их нужно раскрывать.
- Встречаются архивы больше 64 МиБ внутри архивов (49 шт.), поэтому раскрытие через временный файл на том же томе, с лимитами.
- Действие по умолчанию по профилю «Telegram»: **раскрыть** (глубина ≤ 3, остальные лимиты — секция `[limits]` профиля), каждый вложенный архив → отдельная подпапка `content/i001/<имя архива>/`, сведения о нём сохраняются как о входном объекте.

### 4.7. Повторяющиеся имена и масштабы

- 4 027 групп повторяющихся имён, 427 групп файлов одного размера в одной папке.
- Типовые маркеры масштаба в путях: `75mm` (661), `1_6`/`1-6` (713), `1-10` (438), `1_4` (289), `178mm`, `120mm`, `32mm`. Также `Pre Support` / `presupported`, `SFW`/`NSFW`, `Split and Keyed`.
- **Вывод:** подтверждён запрет на дедупликацию внутри ассета (ТЗ 6.5.3). Маркеры — хороший материал для **автоматических предложений логических групп** (масштаб, поддержки, вариант), но только как предложения.

### 4.8. Повреждённые архивы

- `Sanix - Fallout (T60).rar` — ошибка данных при чтении. По ТЗ 6.6 работает строгий режим: импорт останавливается, предлагается частичный импорт.

## 5. Проверка гипотез инвентаризации на этапе M0 (спайки)

Сами данные коллекции не меняются. Спайки читают отобранные примеры только на чтение:

1. Тома RAR, переименованные Telegram (`Sylvanas…`): libarchive против 7z.dll — кто корректно собирает набор из файлов с неканоническими именами.
2. Три «не-zip» `.zip` — определить реальный тип.
3. Набор `Man I Love Figures … part2-4` — поведение при томах с нулевым содержимым.
4. Распознавание кодировок на 20 случайных архивах с mojibake.
5. Скорость: SHA-256 и Deflate-перепаковка одного архива на 3,7 ГиБ (целевой показатель — ограничение по диску).
