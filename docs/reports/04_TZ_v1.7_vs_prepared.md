### Р-2. ADR-0030 «Резервное копирование и восстановление библиотеки»
Предлагаемое содержание:
- полная копия — первый механизм;
- **манифест копии**: формат, LibraryID, дата, версия приложения, состав, ревизии, размеры и SHA-256 ZIP, полнота;
- корзина включается по умолчанию;
- **точка согласования**: `AssetRepository` на короткое время приостанавливает приём `ChangeRequest`, фиксирует ревизии, копирует `userdata`/`state` через `VACUUM INTO` или backup API, затем снимает паузу. Сами ZIP копируются через `AssetSnapshot` (ADR-0025), поэтому чтение не блокируется;
- четыре уровня проверки копии (§14.3.6);
- восстановление по умолчанию — в **новую** библиотеку;
- предыдущая пригодная копия не удаляется.

Инкрементальное копирование и шифрование — не в первом выпуске (так предлагает само ТЗ, вопрос 43 остаётся открытым).

**Место в roadmap:** новый пункт M2 «Библиотека и индекс» — команды `am library backup|restore|verify-backup`. Копия опирается на библиотеку и `userdata`, а критерии 118–120 проверяются только при наличии обоих.

### Р-3. ADR-0031 «Владелец записи библиотеки, режим только чтение, возможности носителя» (дополняет ADR-0025)
- Блокировка `.am/library.lock` (`LockFileEx`/`flock`) удерживается **всё время**, пока библиотека открыта на запись. Второй GUI/CLI-процесс открывает её только для чтения и получает понятную диагностику. IPC — позднее (§14.4.5).
- Блокировка ассета на время фиксации из ADR-0025 сохраняется как внутренний уровень.
- Режим «только чтение»: поиск, просмотр, анализ, экспорт.
- `StorageCapabilities` при подключении библиотеки:
  - чтение и запись;
  - предел размера файла (FAT32);
  - подтверждённость безопасной замены — по итогам S5/S5+, **не** по пробному rename;
  - поддержка блокировок.
- Сетевые ФС по умолчанию открываются только для чтения, пока конфигурация не проверена.
- **Место:** M1 (нужно `AssetRepository` с первого дня) и M2 (подключение библиотеки).

### Р-4. Расширить модель ошибок до начала M1 — *дёшево сейчас, дорого потом*
`am::Error` (уровень `foundation`) дополнить полями:
- `severity`;
- `component`;
- контекст: `job_id`, `asset_id`, `library_id`, `operation`;
- `cause` (цепочка);
- `message_id` — стабильный ключ для перевода вместо готового текста;
- `actions` — допустимые действия: retry, skip, decide, abort.

Коды `Errc` объявить **стабильными** (номера не переиспользуются). Добавить коды `resource_exhausted`, `insufficient_space`, `read_only`, `locked`.

Затрагивает 5–6 существующих файлов и тесты. Оформить в ADR-0027 или отдельной ADR-0032.

### Р-5. Ресурсы и свободное место
- **В M1** (часть протокола фиксации, дополнение ADR-0006/0025): оценка места до транзакции (размер нового ZIP + временные данные + запас), контроль во время записи, отказ без утраты последнего корректного ZIP (критерий 117). Добавить в M1 kill-тест на заполненный диск.
- **В M3** (уровень `jobs`): минимальный `ResourceManager`:
  - раздельные лимиты параллелизма CPU / чтения / записи / внешних процессов;
  - приоритет интерактивных задач;
  - состояния `waiting_resources` и `resource_error`;
  - четыре профиля (экономный, сбалансированный, максимальная производительность, пользовательский).

  VRAM и GPU — в M6. Принудительный контроль чужого кода — через `am-worker` (M9).

### Р-6. Язык интерфейса и документации
- Строки UI и сообщения CLI — **английские**, через `tr()` / Qt Linguist в GUI. В ядре вместо готового текста — `message_id` (см. Р-4). Дополнить `libraries.md` разделом i18n: Qt Linguist для GUI, каталог сообщений для ядра.
- Уточнить в `CLAUDE.md`: русский — язык **обсуждения и документации разработки** (ТЗ, ADR, отчёты, планы). Интерфейс — английский.
- **Вопрос владельцу:** на каком языке писать пользовательскую документацию и техническую документацию формата/API/плагинов (§14.8.9)? Предложение: английский, по логике §14.8.1.
- Пользовательский `CHANGELOG.md` завести с первым выпускаемым CLI (M1). Это не история редакций ТЗ.

### Р-7. Реестр версий форматов

- текущую версию;
- правило несовместимого изменения;

Добавить версии **настроек** (`settings_version` в TOML) и **формата резервной копии** (из Р-2). Зафиксировать правило ленивой миграции ZIP (§14.7.5). Увеличение ревизии при технической миграции — пока [ОТКРЫТО] (вопрос 47).
