# Экспорт ассетов и текущих файлов (T-033)

Полный экспорт — побайтная копия одной ревизии `AssetSnapshot` с прежним AssetID. Выборочный экспорт — обычный ZIP без корневого `manifest.json` и маркера ассета. Пользовательские аннотации, коллекции и решения из `userdata.sqlite` не переносятся. Выборочный экспорт в формате ассета зависит от O-05/O-06 и в T-033 не реализован.

## Имена

Основа — `asset.metadata.title`, при отсутствии или пустом результате очистки — AssetID. Полный экспорт: `<основа>.zip`; выборочный: `<основа> (<пресеты>).zip`, при одних FileID — суффикс `files`. Пресеты перечисляются без повторов в порядке `3d`, `3d_preview`, `slicer`, `all`, через `+`.

`<>:"/\\|?*`, U+0000–U+001F, DEL и C1 заменяются на `_`. Конечные точки и пробелы удаляются. Имена Windows CON/PRN/AUX/NUL/COM1–9/LPT1–9 (включая надстрочные ¹²³, без учёта регистра и перед точкой) получают префикс `_`. Итог вместе с расширением и суффиксами ограничен 255 байтами UTF-8 и 255 единицами UTF-16; обрезка выполняется между кодовыми точками. Unicode не нормализуется. `name_sanitized` сообщает об изменении основы.

Явный `--name` проверяется без очистки, `.zip` добавляется при отсутствии. Ошибка — `am.export.name_invalid`. Имя и FileID можно задавать только для одного ассета. По умолчанию коллизия даёт `am.export.target_exists`; `rename` пробует ` (2)`…` (99)` перед расширением. Верхняя граница 99 — гипотеза.

## Категории `export_categories`, версия 1

При наличии `files[].type.id` используется только он. Иначе используется расширение последнего компонента `storage_path`, без учёта регистра.

| Категория | TypeID | Расширения при отсутствии TypeID |
|---|---|---|
| model | `mesh.*` | stl, obj, mtl, 3mf, ply, amf, fbx, gltf, glb, dae, off, 3ds, step, stp, iges, igs, blend |
| image | `image.*` | png, jpg, jpeg, webp, gif, bmp, tif, tiff |
| slicer | `mesh.stl.*`, `mesh.obj`, `slice.*`, `gcode` | stl, 3mf, obj, lys, chitubox, ctb, gcode |

`3d` выбирает model; `3d_preview` — model, image и текущие FileID из `previews.items`; `slicer` — slicer; `all` — все текущие `files[]`. Явные FileID объединяются с пресетами, порядок остаётся порядком `files[]`. Неизвестный или исторический FileID даёт `am.export.file_unknown`, пустой отбор — `am.export.selection_empty`. Зависимости OBJ/MTL/текстур автоматически не разрешаются. Изменение таблицы требует следующей версии списка.

## Пути и потоки

Корневая папка ZIP совпадает с именем результата без `.zip`. Префикс `content/<InputID>/` убирается, `generated/` сохраняется. Коллизии определяются `unicode::path_collision_key`; второй и следующие пути получают ` (2)`, ` (3)`… перед расширением последнего компонента. Итог перечисляет `renamed[]: {file_id,path}`.

Профиль `plain` проверки путей отличается от `asset` отсутствием требования NFC и предела 200 байтов; предел имени записи — 65535 байтов. Проверки относительности, компонентов, управляющих символов и запрещённых имён сохраняются. Строгий профиль ассетов остаётся значением по умолчанию. Сжатые потоки копируются `ZipWriter::copy_raw`, без перекомпрессии, с прежними CRC и методом; имена записываются как UTF-8 с битом 11.

## Проверка и публикация

Полный экспорт читает удерживаемый источник снимка, без повторного открытия имени активного ZIP. Источник всегда проходит V1–V4. SHA-256 всего ZIP вычисляется при потоковом копировании; временный файл перечитывается с диска, проверяются размер, SHA-256 и V1–V3. `--verify quick` — значение по умолчанию. `full` дополнительно проверяет V4 временного ZIP.

При выборочном экспорте источник проходит V1–V3; выбранные потоки проверяются при raw-копировании по CRC, размеру и SHA-256 из `files[]`. Все записи временного ZIP проверяются повторно, независимо от `--verify`; невыбранные потоки источника не читаются.

Цель — существующий каталог вне библиотеки; последний компонент не может быть ссылкой. Перед записью проверяются свободное место и известный предел размера файла ФС. Временный файл `.am-export-<UUID>.tmp` создаётся исключительно в целевом каталоге. Порядок: запись, сброс на носитель, проверка, checkpoint задания, публикация без замены. Windows использует MoveFileExW с WRITE_THROUGH без REPLACE_EXISTING; Linux — renameat2 NOREPLACE, с резервным link/unlink, затем fsync каталога. При ошибке или отмене временный файл удаляется.

Уборка затрагивает только обычные незанятые файлы со строгим именем `.am-export-<UUID>.tmp` старше `orphan_age` (24 часа — гипотеза). Молодые файлы, ссылки и похожие имена сохраняются.

Живой временный файл удерживает отдельную аренду до окончания публикации: на Windows читающий дескриптор совместим с записью/переименованием, но не с исключительным открытием уборщика; на Linux удерживается `flock`. Защита сохраняется после закрытия writer, во время проверки и checkpoint. Даже после длительного сна старый активный файл не принимается за сироту.

## Очередь и повтор

При доступной записи создаются `export.run` и `export.asset` на каждый AssetID. Ошибка одного ассета не прерывает остальные. Устройства чтения и записи определяются через `detect_media`, аренды выдаёт ResourceManager. В режиме только чтения выполняется тот же экспорт без сохранения заданий и журнала; `queued:false`, `--enqueue-only` даёт `am.export.queue_unavailable`.

Экспорт не меняет данные библиотеки; служебные метки сессии и штатное восстановление при открытии на запись — поведение Catalog, не экспорта (В-6). Допустимая метка индекса — ровно `meta.writer_session`; другие строки и таблицы не исключаются из проверки неизменности. При чистом открытии сравниваются все ZIP, userdata и конфигурация побайтно, все таблицы индекса — по строкам с указанным исключением. В режиме только чтения сравнивается содержимое всех трёх БД без исключений, включая `writer_session`; само появление SQLite `-wal/-shm` изменением данных не считается.

Перед публикацией `JobContext::checkpoint` синхронно сохраняет `{"checkpoint":{"kind":"export.publish","target_name":…, "sha256":…, "size":…, "result":…}}` в `result_json`. Ошибка checkpoint запрещает публикацию. При повторе совпадение имени, размера и SHA-256 существующего файла возвращает сохранённый результат ревизии без повторной записи. Иначе действует политика коллизий. Итог заменяет checkpoint; прогресс остаётся независимым текстовым `stage`.

В доступный на запись `op_log` добавляется код `export` с AssetID, ревизией, режимом, пресетами, числом файлов и исходом. Целевой путь находится только в `detail`, который удаляет обезличивание диагностики. Код CLI: 0 — все ассеты экспортированы или поставлены в очередь; 4 — есть неэкспортированные; 2 — неверные аргументы.
