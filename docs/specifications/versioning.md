# Реестр версий форматов и интерфейсов (ТЗ §14.7.1)

ТЗ v1.7 §14.7.1 требует независимо версионировать девять сущностей. Этот документ — единое место, где для каждой указано:
- где хранится номер версии;
- текущая версия;
- что считается несовместимым изменением;
- как читаются старые версии.

Решение — отчёт 04, Р-7.

| # | Сущность | Где хранится номер | Текущая версия | Несовместимое изменение | Чтение старых / неизвестных версий |

**Служебные машинно-читаемые форматы проекта** (не входят в перечень §14.7.1, но версионируются так же):
- `analysis.v1` — отчёт `am analyze`, ADR-0029;
- `expected.v1` — эталоны fixtures, ADR-0029.

## Матрица возможностей формата ZIP (ТЗ §19.4.18.2)

Для каждой версии формата программа явно объявляет, что она с ней умеет. `recognize`/`read` не означает `write` (§19.4.7.5).

| Версия формата | recognize | read | validate | write | migrate | Примечание |
|---|---|---|---|---|---|---|
| 1.0 | да | да | да (V1–V4) | да | — | Текущая (после публикации) |
| 1.x, x > поддерживаемой | да | да, с сохранением неизвестных ключей | V1, частично V2–V4 | **нет** | — | Ассет открывается только для чтения |
| ≥ 2.0 | да (по `format.id`) | нет | нет | нет | — | `Errc::unsupported` |
| Черновики до 1.0 (`am-asset`, bundle v0.1) | нет | нет | нет | нет | — | Не выпускались; миграции нет (ТЗ §19.6.2, C-02) |

Строки добавляются вместе с поддержкой новой версии; golden ZIP каждой выпущенной версии неизменяемы (§19.4.18.2, §19.4.18.7).

## Правила

1. **Ленивая миграция ZIP (§14.7.5).**
   - Старый ZIP мигрирует только тогда, когда его нужно изменить: миграция становится частью того же `ChangeRequest`.
   - Пакетная миграция — отдельная команда с подтверждением.
   - При обновлении программы массовая миграция автоматически не запускается.
2. **Миграция ZIP транзакционна (§14.7.6)** и идёт по протоколу фиксации (ADR-0006).
   - Сохраняются: AssetID, исходные байты полезных файлов, provenance, история, неизвестные совместимые поля.
   - Техническое преобразование записывается в `history` как операция `format_migrated` с `details{from, to, steps[]}`.
   - Миграция, изменившая постоянные данные, **увеличивает `revision` на 1** одной фиксацией, даже если цепочка шагов длинная; чистая перепаковка — нет (ТЗ v1.8 §19.4.2.6, §19.4.18.3; вопрос 47 закрыт).
3. **Откат исполняемых файлов не равен откату данных (§14.7.10).**
   - Обратные миграции не гарантируются.
   - Перед несовместимым изменением формата программа предупреждает и предлагает создать резервную копию (ADR-0030).
4. **Глубина поддержки старых версий ZIP** определяется после первой стабильной версии формата (§14.7.13).
5. **Новая версия любой сущности** обновляется здесь в той же правке, что и код.
