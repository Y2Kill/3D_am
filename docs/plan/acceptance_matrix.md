# Матрица приёмки (ТЗ §14.9.12)

Решение — отчёт 04, Р-8. Матрица связывает требование с проверкой:
- Requirement ID;
- конфигурация;
- набор данных;
- методика;
- метрика или порог;
- результат;
- статус.

Детализация 16 сценариев импорта (§13.2) ведётся отдельно — в [`coverage_matrix.md`](coverage_matrix.md). Здесь на неё даются ссылки по ID `SC-n`.

## Схема идентификаторов требований

| Префикс | Что обозначает | Пример | Источник |
|---|---|---|---|
| `K-<n>` | критерий приёмки §15 (1–136; 112–136 — [ПРЕДЛОЖЕНИЕ] v1.7) | `K-117` | ТЗ §15 |
| `NFR-14.<раздел>.<пункт>` | нефункциональное требование §14 | `NFR-14.4.2` | ТЗ §14.1–14.9 |
| `SC-<n>` | сценарий импорта (1–16) | `SC-6` | ТЗ §13.2, `coverage_matrix.md` |

- Тесты помечают требования через `::testing::Test::RecordProperty("req", "<ID>")`. Если требований несколько, ID перечисляются через запятую.
- Отчёт трассировки `tools/coverage/req_report.py` (M1) собирает эти метки из JUnit XML ctest и сверяет их с этой матрицей.
- Номера пунктов ТЗ привязаны к версии ТЗ. При перенумерации в новой версии ТЗ ID в тестах обновляются вместе с матрицей.

## Статусы (ровно пять, §14.9.12)

| Статус | Значение |
|---|---|
| **не реализовано** | функциональности нет |
| **реализовано, не проверено** | код есть, проверки по методике нет или она не пройдена полностью |
| **соответствует** | проверка по методике пройдена на указанной конфигурации |
| **не соответствует** | проверка проведена, результат не удовлетворяет требованию |
| **неприменимо к конфигурации** | требование не относится к этой ОС, ФС или сборке |

**Правила заполнения:**
- Измеряемые показатели без согласованного порога записываются как «порог: [ОТКРЫТО]» ([план измерений](../architecture/nfr_measurement_plan.md)).
- Статус «соответствует» для них возможен только после фиксации порога владельцем.
- Неизвестное не записывается как проверенное.
