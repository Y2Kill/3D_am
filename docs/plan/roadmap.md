# План реализации (этапы, вехи и задачи)

**Принципы:**
- Каждая веха заканчивается **работающим вертикальным срезом** с тестами и CLI-командой.
- GUI подключается к уже проверенному ядру (ТЗ 3.1.4–5).
- Номера критериев приёмки (К-n) — из ТЗ §15 (v1.7–1.8: 1–136; 112–136 — [ПРЕДЛОЖЕНИЕ]). Нефункциональные требования §14 — ID `NFR-14.x.y`; статусы — в [`acceptance_matrix.md`](acceptance_matrix.md).
- Числовые нормативы не назначаются до измерений (ТЗ §14.9.13); план — [`nfr_measurement_plan.md`](../architecture/nfr_measurement_plan.md).
- Обязательные проверки затронутой функциональности должны пройти до её выпуска (ТЗ §12.9.11). Покрытие сценариев отслеживается в [`coverage_matrix.md`](coverage_matrix.md).
- Этапность — матрица **поставки**, а не отказ от требований: функции поздних этапов остаются в ТЗ (§19.1).

## Этапы и порядок вех

| Этап (§19.1) | Вехи по порядку | Итог этапа |
|---|---|---|
| **P0** — ядро и прототип | M0 (P0.1) → M1 (P0.2–P0.4) → M2 (P0.5) → M3a (P0.6–P0.7) → итоговые испытания P0.8 | C++20-библиотеки, CLI Windows/Linux, формат ZIP 1.0, безопасное хранение, три базы, импорт файлов/папок/ZIP и экспорт, crash/recovery |
| **P1** — Windows GUI MVP | M3b → M4 → M5 → M6a; из M2 — резервирование и перемещение | Qt 6 GUI + CLI, RAR/7z/тома, теги/категории/поля/происхождение, поиск по хешам и составу, растры и **интерактивный STL**, задания, backup/restore |
| **P2** — расширенная функциональность | M5P → M6b → M7 → M8 → M9 → M10; сцены — новая `minor` формата | Плагины и SDK, конвертация, геометрический/визуальный поиск, сцены, внешнее редактирование |
| **P3** — необязательные интеллектуальные сценарии | M-S → M11 | Автоматизация и локальная LLM; базовые функции от них не зависят |

**Спайки M0 (S1–S7)** выполняются в начале независимо от этапа функции: они снимают риски, а не поставляют возможности.
- S7 нужен для утверждения формата 1.0 (M1).
- S1 нужен для M3b.
- S4 — для M6a.
- S6 — для M5P.
