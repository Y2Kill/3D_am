# Сквозные испытания T-035

Шесть сценариев вызывают настоящий `am`, закрывая каждый процесс перед следующим
шагом. Описания находятся в `CASES`, рецепте `SOURCE` и ветвях `run_case`:
сценариев мало, а идентификаторы создаются во время запуска; отдельный язык JSON
для зависимых команд усложнил бы проверку. Ожидания задаются по спецификации,
не записываются из вывода программы.

| CTest | Проверка |
|---|---|
| `e2e-import-transfer` | Каталог, ZIP и вложенный ZIP → импорт A → полный экспорт → чистая B |
| `e2e-ready-transfer` | Каждый положительный golden, включая новую minor, непрозрачные данные, claims и точные числа; отдельная A из-за совпадающих ID |
| `e2e-copy-transfer` | Новый ID, ревизия 1, история independent_copy/source_asset, неизменные потоки; оба ассета переносятся |
| `e2e-index-rebuild` | Инкрементальный индекс, rebuild, удаление/открытие/rebuild, sync --full: четыре равных снимка |
| `e2e-trash-roundtrip` | Корзина, отказ экспорта, восстановление, перенос; SHA ZIP прежний |
| `e2e-selective-export` | Четыре пресета: имена и SHA выбранных файлов, без манифеста/маркера ассета |

На Linux запрет записи проверяется явными отказами `storage_read_only`, без SKIP
самих e2e-тестов. Цепочки записи отмечаются NOT_APPLICABLE; чтение Windows-пакета
проверяется отдельно. Обратное направление переноса не проверяется.

## Снимок и изоляция

`index_snapshot` открывает SQLite в `mode=ro`, читает все логические таблицы,
включая пустые, и сохраняет имена столбцов. Полное сравнение использует расширение
`expect_match(exact=True)`; прежнее сравнение подмножеств T-034 не меняется.

Адресные исключения находятся в `LOCAL_FIELDS`/`LOCAL_META`:

- A ↔ B: `assets.rel_path`, `in_trash`, `zip_mtime_ns`;
- внутри A: `assets.rel_path`, `in_trash`; **mtime сравнивается**;
- в обоих случаях: строки `meta.rebuilt_at`, `meta.writer_session`;
- локальный INTEGER PRIMARY KEY `suggestions.id`;
- физические таблицы FTS5 с типом `shadow` заменены видимыми строками FTS и
  `fts5vocab(instance)`. `doc` и `fts_rowid` заменены полным содержимым строки,
  связи и повторения сохранены.

`rebuild_required`, размер ZIP и SHA ZIP сравниваются всегда. Неизвестные таблицы
и столбцы не исключаются. Внутри A одинаковый mtime дополнительно подтверждает,
что rebuild/sync не переписывают ZIP. Изменение rowid физического FTS-хранилища
при перестроении допустимо, изменение текста и токенов — нет.

Перед созданием B исходник и A переименовываются, прежние пути проверяются на
отсутствие. HOME/USERPROFILE/LOCALAPPDATA/XDG_STATE_HOME/TMP/TEMP/TMPDIR у B свои.
Защитная проверка аргументов запрещает и прежние, и переименованные пути, и
окружение A. В A добавляются локальные favorites, в B все таблицы userdata пусты.
Негативные самопроверки работают без CLI:

```text
python -I tests/e2e/test_e2e_self.py
```

Для нового сценария добавьте запись `CASES`, явные ожидания в `run_case` и CTest
с метками `e2e;req:...`. После изменения нормализации добавьте отрицательный тест.
Таймауты процессов/CTest и предел пакета 2 МиБ — гипотезы для защиты прогонов,
не нормативы производительности продукта.

## Windows → WSL / CI

Windows CTest `e2e_portability_bundle` создаёт `build/e2e/portability/`: полный
экспорт синтетического импорта и всех положительных golden, четыре выборочных
ZIP, обычный ZIP библиотеки из трёх ассетов (один в корзине), снимки Windows и
`bundle.json` с SHA-256/размерами. Golden с одинаковыми ID экспортируются из
разных библиотек. Проверка не требует их исходных библиотек или исходника.

Из корня проекта в WSL запускается **та же команда, что в CI**:

```sh
python3 -I tests/e2e/check_portability.py --am build/linux-cli/bin/am --bundle build/e2e/portability --work build/e2e/portability-linux
```

Сначала проверяются все хеши, затем V1–V4/inspect каждого ZIP с нормативными
вердиктами golden (partial/newer_minor допустимы), содержимое выборочных ZIP,
индекс/FTS/корзина распакованной библиотеки, readonly export с `queued:false`,
отказ add-ready и неизменность всех строк трёх БД и SHA ZIP.

Локальная проверка YAML использует уже установленный в WSL PyYAML:

```sh
python3 -I tests/e2e/test_e2e_self.py --workflow .github/workflows/ci.yml
```

`portability-linux` зависит от `win-cli`. Межзаданийная передача артефакта,
`needs` и пять зелёных заданий подтверждаются управляющим после публикации через
`tools/publish_public.sh`. Локальная ветка не публикуется исполнителем.
