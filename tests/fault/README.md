# Отказы T-036

Матрица — `docs/plan/fault_matrix.md`. Новые проверки дополняют существующие
kill/space/recovery-тесты; опубликованные корпуса T-034/T-035 не меняются.

`FaultState.*` проверяет пересоздание state, исторический reason/time в info,
чтение повреждённых страниц, откат и политики orphan. Дешёвое открытие после
чистой сессии сохраняется. `FaultSqlite.*` использует тестовую VFS, делегирующую
настоящему движку SQLite все операции, кроме выбранного xWrite→SQLITE_FULL.
`FaultProcess.*` убивает дочерний процесс через TerminateProcess/SIGKILL:
деструкторы процесса не выполняются. На каждой применимой точке три повтора.
`run_fault_process.py` и `run_fault_unit.py` после обычного восстановления
сравнивают все логические таблицы/FTS с rebuild через index_snapshot из T-035,
включая mtime ZIP и rebuild_required.

Внутренние hooks create_sink экспорта/диагностики — только API внедрения для
тестов. Они не доступны через am, окружение, конфигурацию или плагины.
Все временные данные остаются в .cache/. Числовые ограничения тестового тома,
таймауты ожидания и размеры заполнителя — гипотезы защиты прогонов.

## Малый NTFS-том: только запуск владельцем

Исполнитель не запрашивает UAC и не запускает Create/Remove от администратора.
Владелец открывает PowerShell **с правами администратора** и выполняет из корня:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/test_volume/small_volume.ps1 -Create
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/test_volume/small_volume.ps1 -Status
$env:AM_SMALL_VOLUME = Join-Path (Get-Location) '.cache/small-volume/mnt'
ctest --test-dir build/win-cli -L small_volume --output-on-failure
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/test_volume/small_volume.ps1 -Remove
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/test_volume/small_volume.ps1 -Status
Remove-Item Env:AM_SMALL_VOLUME
```

`-ExecutionPolicy Bypass` в этих командах относится только к создаваемому
процессу PowerShell, не меняет системную политику исполнения. Его может
понадобиться явно указать владельцу, если выполнение .ps1 запрещено.
Поддержка Hyper-V/New-VHD не требуется: VHDX создаётся встроенным DiskPart,
подключается Storage cmdlets без буквы диска и монтируется в папку проекта.
Размер — 64 МиБ (гипотеза). Служебная запись owner.json привязывает операции
к точному файлу и папке. Неизвестный образ не форматируется и не удаляется.
Remove не удаляет содержимое папки рекурсивно; сначала удаляется точка доступа,
образ отключается, затем удаляются только известные файл и пустая папка.

Повторный Create использует тот же образ. Повторный Remove без образа — успех.
Если прервано создание до записи owner.json, неизвестный образ требует ручной
проверки владельцем: скрипт не будет угадывать, можно ли его форматировать.

Без AM_SMALL_VOLUME Windows-тест возвращает SKIP 77 с причиной. Классификатор
не ослабляется: фактическая классификация выводится отдельно, библиотечные
операции тестируются с подставленными capabilities и настоящими файлами.

## WSL / Linux

Малый tmpfs разрешён только в отдельном mount namespace через
`unshare --user --map-root-user --mount`, без sudo и изменения глобальных
точек монтирования. При недоступном namespace/mount — SKIP 77 с причиной.
Обычная политика read_only_default не меняется; R работает на unit-уровне с
подставленными capabilities. После процесса namespace и mount исчезают.
Метка `periodic;small_volume` исключает эти проверки из обычных прогонов.

После сборки: `ctest --preset linux-cli -L small_volume --output-on-failure`.
Ту же метку запускает отдельный шаг существующего задания linux-cli; новых
заданий CI нет. Драйвер сам проверяет unshare, монтирует tmpfs 32 MiB только
в дочернем namespace и снимает его в finally. Без этой возможности — явный SKIP.
Windows-драйвер никогда сам не подключает том и не повышает права.

Восемь R-сценариев: оценка места change; реальный обрыв записи change;
полный экспорт; запись временного ZIP импорта; SQLITE_FULL индекса; диагностика;
best-effort журнал приложения; запись конфигурации init. Каждый сценарий
заканчивается проверкой подтверждённых данных и сравнением полного индекса
после sync с rebuild. Фактический классификатор выводится отдельно; тестовые
capabilities не меняют политику read_only_default на Linux.

На NTFS через папку подключения DiagnosticExportFull проверяет явный
am.diag.local_only и сохранность данных, но R помечается NOT_APPLICABLE.
InitConfigurationFull на NTFS допускает чистый insufficient_space или полную
валидную библиотеку (маленький TOML может не занимать кластеров); исход есть в
init_configuration_outcome. На tmpfs обе проверки по-прежнему требуют ENOSPC.
Драйвер проходит все случаи и печатает сводку passed / not_applicable / failed;
детали сохраняются в summary.json каталога прогона. Отдельный каталог каждого
случая удаляется и после отказа, включая таймаут до появления XML. Логи и XML
на основном диске сохраняются. Windows-драйвер не отключает том владельца.

K-сценарии используют по три повтора на точку. Три независимые библиотеки
могут проверяться одновременно (гипотеза параллелизма прогонщика), но шаги
одной библиотеки всегда последовательны. Оракул хранит доказанный SHA новой
ревизии до второго убийства recovery; удаление уже обработанной строки журнала
не превращает такую ревизию обратно в старую.

Отключение питания и долговечность контроллера здесь не проверяются.
После replace подтверждённый ZIP не откатывается из-за ошибки производного
индекса: сохраняется insufficient_space в причине предупреждения и проверяется
восстановление после освобождения места (уточнение О-3 по В-6).
